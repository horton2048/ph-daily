## 是做什么的（如实复述，不评价）

Keystroke 是一个 **all-in-one 的"内部 agent / AI 系统"构建平台**：用自然语言描述你需要的 agent，内置的 agent 帮你构建它、连接你的工具、跑测试、部署到团队共享工作空间。也可以让 Cursor、Claude Code、Codex 等 coding agent 直接以 TypeScript 编写——一切产物是**普通 TypeScript**，可以进 git、grep、测试、review，并可跑在任何地方。

官方定位原文："Keystroke is an all-in-one platform for building powerful AI agents. Describe the agent you need, and Keystroke builds it, connects your tools, tests it, and deploys it to a shared workspace. Give agents memory, workflows, triggers, approvals, and access to 1,000+ integrations." 开场评论强调：创建 agent 只是把它用进公司的很小一部分，还需要 integrations、credentials、memory、workflows、triggers、approvals、observability 和一个团队能真正使用/改进的共享空间——这些通常散落在 agent frameworks、scripts、infrastructure、automation tools 里。

开源形态：Keystroke 分两层——source-available 的 standalone runtime（ELv2，可自托管）+ Keystroke Cloud（商业托管，另有独立授权）。团队可在 Keystroke 里与 agent 聊天，也可通过 Slack/Teams 使用，共享工作空间协作管理 credentials、context、skills。当前 open alpha。

## 解决什么问题（事实层面，不判断值不值得解）

- **落地断层**：创建 agent 只解决一小部分；让它真正跑在公司里还需要集成、凭据、记忆、工作流、触发、审批、可观测性，这些今天散落在不同工具里（Blake 开场评论）。
- **视觉平台 vs code-first 的两难**（Show HN 自述）：n8n/Zapier 这类视觉平台好上手，但系统长大之后难测试/review/debug；Trigger.dev、Mastra、Vercel 这类 code-first 工具则要自己造 UI、runtime、权限、credentials——两个方向都不完整。
- **"冷启动"的重复交代**：团队每次用 AI 工具都要重新交代背景（评论区用户 Vaishnavi Goel 在 Kiro Crew 帖子的同类表述；本产品评论区亦有"记忆/上下文延续"诉求）。
- **技术与非技术同事共用**：想让"一个人建的东西成为全公司能用、能理解、能改进的东西"，给技术与非技术同事同一个创作空间。
- **agent 的可观测性**：每个 run 要 durable、可观测、团队可检查。

## 怎么做的（技术原理/机制，事实层面）

来源：GitHub README + YC 公司页 + Show HN + PH maker 评论

- **核心原语**：**Actions**（类型化、可复用的单元）、**Agents**（模型驱动的开放式路径）、**Workflows**（durable 的确定性步骤，带 step replay）、**Triggers**（cron/webhook/poll/app events）。
- **代码优先**：workflow 是普通 async TypeScript，写在用户自己的 git 仓库里，用 Zod schema 做输入/输出校验、Vitest 可测，由 coding agent 来写、团队按代码方式 review——差异化宣称是"n8n for coding agents"。
- **能力面**：内置 memory、web search、code execution、persistent workspaces、subagents、MCP tools；1,000+ 集成定义 + 任意 HTTP API/MCP server。
- **触发与部署**：agent 可跑在 schedule/app events 上、自建触发器、生成轻量 app 和 dashboard；多步任务无人值守跑完。
- **Durable execution**：重试时 replay 已成功的步骤；credentials 与代码分离。
- **模型层**：内置 AI gateway（OpenAI/Anthropic/Google/Groq/xAI 等 300+ 模型）按厂商列表价 1.1x 加成；自带 API key 不收费。
- **技术栈**：TypeScript；pnpm workspaces + Turborepo monorepo（apps/packages/docs/playground/templates）；Node `^22.18.0 || >=24.0.0`；CLI `@keystrokehq/cli`（deploy/prompt/run/triggers/credentials）。
- **许可证**：ELv2——source-available，允许自托管，但**禁止把核心功能作为托管/管理服务提供给第三方**（即非 OSI 批准的"开源"；Cloud 部分为单独授权的企业代码）。

## 定价 / 商业模式

（https://www.keystroke.ai/pricing，2026-08-06 抓取）

- **Hobby（$0/月，含 $1/月用量额度）**：1 项目、5GB 存储、5 并发、10min 超时、60 req/min、日志留 7 天。
- **Pro（$20/月，含 $20 用量额度）**：5 项目、50GB（超出 $0.25/10GB）、10 并发、30min 超时、300 req/min、日志留 30 天、优先支持。
- **Organization（定制，联系销售）**：RBAC、SSO、audit logs、agent guardrails、无限并发、企业级安全。
- **用量计费**：agent run $0.01/次、workflow run $0.01/次、空 poll trigger $0.005/次、web search（Exa）$0.007/次、web fetch（Exa）$0.001/次、沙箱计算约 $0.067/小时。
- **模型计费**：内置 AI gateway 按厂商列表价 1.1x；自带 key 不收费。
- **免费试用**：注册送 $20 credits（与 PH 描述一致）。
- **商业模式要点**：开源 runtime（ELv2）做获客 + Cloud 托管订阅（免费档 + usage-based）变现——评论区的官方答复"Currently make money from our cloud offering, which has a free plan with usage-based pricing"。

## 关联信息 / 生态

- **转型史**（Show HN）：Buster 内部搭 agent 时被视觉平台和 code-first 工具两头卡住，于是自建 Keystroke 并全职 pivot——从"数据平台"转向"agent 构建平台"。
- **竞品定位**：官方/第三方措辞"**n8n for coding agents**"。vs n8n：n8n 更成熟（20 万+用户、19.6 万 stars、$2.5B 估值、Sustainable Use License），视觉搭建/非开发者/生产关键流程仍选 n8n；独立评测给 open alpha 状态 Keystroke 评 6.5/10（provisional）。vs Zapier：PH 用户评价"Feels like an easier Zapier or n8n"。
- **团队协作形态**：agent 可在 Slack/Teams 里用；团队共享 workspace、共享 context/skills、管理 credentials。
- **GitHub 数据点**（2026-08-06 抓取）：57 stars / 11 forks，仓库建于 2026-07-13（公开上线日），最近推送 2026-08-05。
