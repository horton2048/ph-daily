## 是做什么的（如实复述，不评价）

Muse Code 是 Meta 推出的一个终端命令行编码智能体（beta），在 macOS 和 Linux 上运行，安装方式是一行命令（`curl -fsSL https://dev.meta.ai/install.sh | bash`），没有独立图形应用。它面向"长时程"（long-horizon）的软件工程任务：对大型代码仓库做规划变更、写代码、并验证结果（Meta AI 博客原文："planning changes, writing code, and validating the results"）。运行时由一条主智能体循环配合一组"持续存在的后台子智能体"组成，子智能体在整个会话期间保持活跃；任务足够大时，会分发到隔离的 git worktree 里并行执行的子智能体，且不改动用户的工作副本。它带本地追加式事件日志，记录每次模型调用、工具运行、审批和编辑，崩溃后可精确恢复。内置三个技能：`/plan`（产出需审批的计划）、`/grill`（压力测试计划直到站得住）、`/goal`（向目标完成推进）。底层模型是 Muse Spark 1.2，该模型同时通过 Meta Model API 对外开放。

## 解决什么问题（事实层面，不判断值不值得解）

- 大仓库、多文件、多小时的编码任务：传统单轮问答式 agent 上下文不延续、中途失败丢状态。Meta 的解法是"长时程"定位 + 持久后台子智能体 + 崩溃可恢复的事件日志。
- 长任务中途崩溃丢失进度：事件日志是 write-ahead 式（先记意图再执行），崩溃后从日志精确续跑（MacRumors / explainx 均描述）。
- 并行开发的冲突问题：子智能体在隔离 worktree 并行执行，Meta 宣称"你的工作副本永远不会被碰"，并称内部测试中同时为游戏构建六个功能无冲突（Zuckerberg 在 TechCrunch 的表述，厂商自述，未经独立复现）。
- 开发者手动做重复信息收集：后台子智能体持续活跃、自行决定何时回报主智能体，减少多步任务中的延迟与人工"steering"（Meta 博客原文）。
- 目标场景：仓库级重构、bug 分流、测试生成、GPU kernel 优化（MarkTechPost 归纳的官方建议场景）。

## 怎么做的（技术原理/机制，事实层面）

- 主循环 + 异步后台智能体：一条简单 agent loop 加一组持续活跃的 async background agents，"避免重复信息收集"，自己决定下一步与何时回报主智能体（Meta AI 博客）。
- 隔离 worktree 并行：任务足够大时 fan out 到多个子智能体并行，运行在隔离 worktree，用户工作副本不被改动（TechCrunch 引 Zuckerberg）。
- 本地事件日志：每条 model call、tool run、approval、edit 都追加到本地日志，作为单一事实来源，"replay-exact and restart-safe"，崩溃后精确续跑（Meta AI 博客 / MacRumors）。
- 内置技能：/plan（审批门控计划）、/grill（压力测试计划）、/goal（目标推进）（Meta AI 博客）。
- 模型 Muse Spark 1.2：1.1 的编码向更新；在编码任务上显著扩大训练算力、扩展训练环境多样性；用"拒绝采样的 harness 轨迹 + goals/compaction/subagents 的配方优化"与 Muse Code 联合训练；专门在长时程任务（整仓库生成、大型端到端项目、auto-research）上训练；自举：用 1.1 生成的困难编码环境与指令模板 + 模型自评候选方案，产出了 1.2 的训练数据（Meta AI 博客 / MarkTechPost）。
- 验证方式：写代码、编译、剖析、逐步改进（kernel 案例：相对给定 baseline 实现迭代 kernel 性能）；/grill 技能压力测试计划。
- 可用性：Muse Spark 1.2 今天在 Muse Code 与 Meta Model API 可用，"expanded global access"；Muse Code 本体为 beta；未发布模型权重（MarkTechPost 明确"launch post 不提及可下载权重"）。
- 基准测试（Meta 自选对比，explainx 强调为厂商自选图，非独立榜单；数字来自 explainx.ai 转述 Meta 图表）：
  - Terminal-Bench 2.1（全部 89 题，pass@1 over 5 attempts，隔离 Daytona 云沙箱）：Opus 5(max, Claude Code) 86.7%；Muse Spark 1.2(Muse Code) 82.9%；GPT-5.6 Terra(max, Codex) 81.8%；Grok 4.5 81.6%；Gemini 3.6 Flash 78.9%；Muse Spark 1.1 76.2%。
  - DeepSWE v1.1（113 题、91 仓库、5 语言）：Opus 5 65.0%；GPT-5.6 Terra 64.8%；Muse Spark 1.2 59.3%；Grok 4.5 56.6%；Muse Spark 1.1 53.0%；Gemini 3.6 Flash 40.0%。
  - Meta Internal Coding Bench（440 题，来自内部真实 PR）：Opus 5 79.4%；Muse Spark 1.2 70.6%；Muse Spark 1.1 68.3%；GPT-5.6 Terra 65.4%；Gemini 3.6 Flash 63.9%。
  - 模型页另列 Muse Spark 1.1 在 Terminal-Bench 2.1 上为 80.0（MarkTechPost）。
- Kernel 案例研究（Meta AI 博客 / MarkTechPost）：迭代式 GPU kernel 优化，1,000+ 次工具调用、最长运行 24 小时、NVIDIA Hopper GPU；KDA 的 baseline 是 FLA Triton 实现，禁止直接导入第三方 kernel 库；MLA 用两 kernel Triton 流水线，对 PyTorch 参考（batch 1、64 heads、seq 8192、latent 512）。

## 定价 / 商业模式

- 两条 API 价位（MacRumors 2026-08-05，具体数字来源为报道）：
  - Standard 档：$1.25/百万输入 tokens，$4.25/百万输出 tokens；不让 Meta 用你的 prompt 训练模型。
  - Contributor 档：$0.10/百万输入 tokens，$0.20/百万输出 tokens；条件是你授权 Meta 用你的 prompt/completion 训练未来模型。输入便宜约 12.5 倍、输出约 21.25 倍（报道口径"up to 20x less"）。
  - 限流：Contributor 档 60 req/min、2,100,000 tokens/min；Standard 档 3,000 req/min、4,000,000 tokens/min。
- Zuckerberg 官方口径仅称"It's easy and low-cost to get started. Install Muse Code with one line and you can start on our contributor tier."（explainx 引述）。具体价位部分来自二手转述（explainx 明确标注 secondhand，非 Meta 定价页），PH maker 评论称"Contributor API pricing is unusually low if you're comfortable with your content being used for product improvement"。
- 商业模式：闭源/托管模型按 token 计费（Muse Code harness 免费安装，费用在模型 API 侧）；权重未开源；开源状态未定（Zuckerberg 被问时答"I'll have more to share on that soon"）。
