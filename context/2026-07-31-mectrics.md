## 是做什么的（如实复述，不评价）

mectrics 是一个原生 macOS 菜单栏系统监视器，MIT 开源、免费。它在菜单栏常驻显示 CPU、内存、电池、网络、磁盘、GPU、温度、风扇等读数；每个模块由用户在"菜单栏构建器"里点击 live preview chip 自由组合，缺失硬件自动隐藏（无风扇的 MacBook Air 不显示风扇模块）。每个状态项点击展开详情 popover（CPU 显示每核负载 + top processes，Disk 显示容量环 + 实时读写吞吐等）。

特色功能 **Compact Health**：把整机状态折叠成一个菜单栏项，仅当某个持续异常时才发声——"短暂尖峰不算新闻"。规则可以盯某个数字阈值，也可以直接盯 macOS 自己上报的状态（CPU/GPU 被降频散热、kernel 内存压力）。

v1.4.0 起新增只读 CLI `mectrics`（在签名 app bundle 内），把告警规则暴露给脚本/cron/agent：`mectrics check` 退出码 0/1/2（健康/越限/无法判定），`--json` 输出详情，`alerts watch --json --heartbeat` 流式输出告警事件。

## 解决什么问题（事实层面，不判断值不值得解）

- 长时间批处理/本地模型任务时 Mac 静默降频，事后才察觉"怎么这么久"——PH 评论区用户 Omri Ben-Shoham 原话："I've had my mac silently throttle during long batch jobs before and only noticed afterward from how long everything took"
- headless Mac mini（跑 agent job / 本地模型推理）没有可视菜单栏，传统菜单栏监视器失效——评论区用户 Dale Mooney、Gal Dayan 都提到这点
- 现有方案二选一：iStat Menus 收费闭源、Stats 等开源深度不够；Activity Monitor 需要切窗口、不能常驻
- 多数监视器只报 raw 数字（温度高 ≠ 真的降频；内存 95% 满 ≠ 有问题），用户要自己解读
- 隐私敏感用户对"上传遥测"反感，即使是匿名 opt-out

## 怎么做的（技术原理/机制，事实层面）

- 原生 macOS app，Swift 6 编写，要求 macOS 15 (Sequoia)+
- 引擎 `MetricsKit`：UI 无关的 SwiftPM 包，包含 provider、自适应调度器、预分配 ring buffer store
- **Compact Health + 告警规则**：规则盯数字阈值或盯 macOS 自报状态（`ProcessInfo.thermalState` 的 thermalPressure、kernel memory pressure）。规则需持续触发一段时间才发声，避免尖峰误报
- **Energy Guard**：采样频率随电源/低电量模式/热压力自适应——AC 时每秒采样、电池时每 2 秒；屏幕睡眠/锁屏/他人会话时降速，回来时立即恢复并取新鲜读数
- **固定宽度菜单栏**：每项预留最坏宽度 + 右对齐等宽数字，值变化不让菜单栏横向跳动
- **缺失读数显示 dash，不伪造 0**——硬盘拔出后吞吐走"无流量"而不是 wraparound 成天文数字（v1.4.0 修了一个"拔外置硬盘后磁盘吞吐报 ~10⁹⁹ 字节/秒"的 bug）
- **零遥测**：无 analytics、无 identifier、无 crash report。app 唯一能发出的网络请求是用户手动触发的更新检查（默认关闭），用 Sparkle appcast + pinned EdDSA 公钥验证
- **CLI 自动化契约**：退出码 0（健康）/1（越限）/2（无法判定）；`--json` 详情；`alerts watch --json --heartbeat` 输出 tagged NDJSON（ready/heartbeat/alert/status 记录），让消费方能区分"安静"和"采样已停"；启动信息走 stderr、JSON 走 stdout，管道机读友好
- 签名：Developer ID 签名 + Apple notarization + Hardened Runtime
- 体积：发行版 ~3.8–4.4 MB；idle 内存 ~24–25 MB（phys_footprint，Activity Monitor 同口径）；约 1 wake/sec
- 项目用 xcodegen 生成 Xcode 工程；CI 在 GitHub Actions

## 关联信息 / 生态

- **MetricsKit**：UI 无关的 SwiftPM 引擎，可独立使用
- **WidgetKit widgets**：small/medium/large，通过 App Group snapshot 喂数据
- **Diagnostics**：本地系统摘要，可复制/导出纯文本
- **Attention Log**：本地、可导出的告警触发记录
- **明确 non-goals**（README 公开列出，issue 提了会被关掉并指回这里）：不做任何遥测、不做账号/云同步/companion service、不监控机器外部（远端主机/SaaS 配额/容器集群）、不主动处置（不杀进程/清缓存/改系统设置——而是把你交给 Activity Monitor / System Settings）、不做基准测试/压测、不做其他平台（仅 macOS，无 iOS / Linux 版）、不做主窗口（菜单栏即界面）
- 竞品：iStat Menus（闭源收费）、Stats（开源免费）、RunCat、MenuMeters、NotchNook、Batterygo（PH Alternatives 页列出）

## 评论区反馈（事实摘录，不评价）

- **Nikita Upadhayay**：描述里写了 temperature/fans，但菜单栏 picker 只有 6 模块，问是否 planned。**Faruk 回复**：温度藏在 CPU/Memory/GPU 模块里；风扇应在有风扇硬件的 Mac 上独立显示，发现一个检测 bug 已修并在下版发布；随后在 v1.4.0 落地并回复用户。
- **Omri Ben-Shoham**：Mac 静默降频要事后才发现，问 Compact Health 能否抓 throttling。**Faruk 回复**：app 已读 `ProcessInfo.thermalState` 但只用于自家采样退避、从未对外暴露；下版会暴露；随后 v1.4.0 实装并回复。
- **Jacob Sherwood**：iStat 老用户，问迁移理由。**Faruk 回复**：不主张比 iStat 深度更高；差异是更安静（Compact Health 而非盯多个数字）、持续告警忽略尖峰、零遥测、免费开源；下版加只读 CLI / JSON snapshot / 告警事件给 headless 场景；随后 v1.4.0 落地。
- **Dale Mooney**：headless Mac mini 跑 agent job，菜单栏永远不看，想要 CLI/JSON 输出告警，并细化要求 `mectrics check` 返回非零退出码而非要解析的输出；进一步要求三态退出码（0 fine / 1 rule firing / 2 cannot determine）以区分"安静"和"采样已停"；要求 `alerts watch` 加 heartbeat。**Faruk 回复**：全部接受并实装，8 小时后回复"已发布 v1.4.0"。
- **Gal Dayan**：headless Mac mini 跑本地模型，担心监视器自身增加后台负载。**Faruk 回复**：主 app idle ~60–65 MB（注：README 写 ~24 MB，主 app 与 CLI 数字不同口径），CLI 因为跳过 UI 会更低占用；采样自适应 AC/电池。
