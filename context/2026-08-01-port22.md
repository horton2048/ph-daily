## 是做什么的（如实复述，不评价）

Port22 是一个 **iPhone app + Mac 端 binary** 的组合，把电脑上正在跑的编码 agent（Claude Code / Codex / OpenCode 等）的会话状态实时镜像到手机上。用户在手机上能读到 agent 的实时 transcript（每 token 流式显示）、收到 agent 完成或等待审批的推送通知，并在手机上点击 agent 真正呈现的选项按钮（不是猜测的 y/n）。Mac 端是一个 binary 监控用户指定的终端会话，无需 wrapper、专用 terminal 或配置；iPhone 端通过 iCloud 配对（同一 Apple ID），无需新建账号或扫码。

## 解决什么问题（事实层面，不判断值不值得解）

- **Agent 长任务被审批卡住**：创始人原话——"我启动一个长 agent 任务，走开，回来发现它花了 20 分钟在等我批准一个文件编辑"。Agent 跑长任务时人不在电脑前是常态。
- **手机审批靠猜按键**：现有方案用手机远控终端时，回车键是"猜"——agent 可能问的是 Y/N，也可能是多选项菜单，盲按经常选错。Rabnoor Singh 评论指出 enter-key 猜测"fails invisibly"（静默选错，比明显失败更糟）。
- **多 agent 并行监控**：开发者同时跑多个 Claude Code / Codex 会话，需要一眼看到哪个在跑、哪个在等人。
- **目标场景**：长跑 agent 任务（夜间重构、大规模迁移）、离开工位时监控、多会话并行。

## 怎么做的（技术原理/机制，事实层面）

来源：tryport22.com + PH 创始人评论区

- **Mac 端 binary**：单一 binary 监控用户指定的终端会话，不入侵 workflow。
- **支持的终端**：Ghostty、kitty、Alacritty、WezTerm、tmux、Terminal.app。**不支持 Warp 和 IDE 内置终端**。
- **支持的 agent**：Claude Code、OpenCode、Codex；OpenClaw、Hermes 标注 coming soon。
- **配对方式**：通过 iCloud（同一 Apple ID），"no new login, no QR dance"。
- **网络**：Wi-Fi 下走 LAN 直连；脱离局域网时自动切换到加密 relay 走蜂窝。Relay "forwards ciphertext and never holds the keys"——只转发密文，无法读代码。公司存储 "0 bytes of code"。
- **加密**：端到端加密在 Mac 和 iPhone 之间。
- **审批 UX**：手机上显示 agent 真实呈现的选项作为按钮，不是猜测的 yes/no。Diff view 和 live terminal jump 仍在开发中。
- **通知**：推送通知 + Dynamic Island + 锁屏 widget 显示会话状态。
- **签名**：macOS 公证（notarized），支持 Apple Silicon 和 Intel。

## 评论区反馈（事实摘录，不评价）

- **Martín Herrán**（质疑）：手机审批会不会让人决策更草率？创始人回复承认："i've caught myself approving things i would have read twice at my desk."（承认手机审批确实会让人更草率）
- **Asad M.**：diff 是否在审批卡上显示是采用与否的决定因素；建议 diff ≤20 行默认展示在卡上。报名 beta 测试真实 4 小时会话。
- **Swati Paliwal**：审批时显示什么 context？创始人：显示真实问题+真实选项按钮+会话历史；rendered diff view 和 live terminal jump 仍在进行中。
- **Raffay Sajjad**：网络怎么走？创始人：Wi-Fi 直连 + 蜂窝时加密 relay。
- **Rhett**：建议对常见 prompt（小文件编辑）设默认自动审批。创始人：planned feature，"between auto mode and manual"。
- **Rabnoor Singh**：enter-key guessing "fails invisibly"——静默选错比明显失败更糟。
- **Arash Rahimi**："tapping the actual option it offered instead of guessing a keystroke is the detail that sells this"——点真实选项而非猜按键是卖点。
