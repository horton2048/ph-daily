## 是做什么的（如实复述，不评价）

MiniMax H3 是 MiniMax 推出的**通用多模态生成模型**（general-purpose omni-modal generation model），核心能力是**生成 2K 分辨率视频并自带原生立体声（native stereo sound）**。它把文本、图像、视频、音频作为统一上下文输入，能执行文本生视频、图生视频、视频参考与编辑、音频参考、多镜头叙事、品牌物料（含准确文字渲染与包装视觉）等任务。同一模型还覆盖 T2I、T2A、音视频联合生成，强调"一个模型覆盖以前被拆成多个专家模型的任务"。

发布方将其定位为"开放权重（open-weight）通用多模态生成模型"，技术博客明确"API 现已上线，权重即将发布（the weights are coming）"。

## 解决什么问题（事实层面，不判断值不值得解）

- **多模态创意工作流被工具割裂**：以往图像生成、视频生成、音频生成、编辑、参考（subject reference）被切分为多个独立专家模型，跨模态与跨任务组合难以在一次请求里完成。
- **品牌/商用物料对"成品感"的要求**：动态海报、产品网站视频、广告电商物料对准确文字渲染、品牌色、镜头节奏、立体声有要求；视频模型"出一帧画面"不够，需要 typography/motion/pacing/sound 协同（H3 评论区 Ridhwik Vinod、Asad M. 等围绕品牌保真度与文字渲染提问）。
- **闭源视频生成迭代慢、生态封闭**：H3 博客称闭源模型长期主导视频生成，迭代慢、开源生态弱于 LLM 领域；H3 以"开放权重 + 低门槛 API"切入。
- **目标场景**：电影开场标题、产品网站动态视觉、动画海报、广告与电商内容、商业创意内容规模化生产。

## 怎么做的（技术原理/机制，事实层面）

来源：MiniMax 官方技术博客（minimax.io/blog/minimax-h3，2026-07-31）

- **统一上下文输入**：text / image / video / audio 在一次请求内混合，通过自然语言指令告诉 H3 从每个参考中"借"什么（角色、镜头运动、声音、视觉风格）。
- **核心技术组件**（官方命名）：
  - **H3-Contextual Omni Representation**：自建专用模型 + 全模态理解管线，把源素材（约 100K tokens 推理）蒸馏为平均约 4K tokens 的描述；语言作为可泛化的"桥"统一所有任务。
  - **H3-VAE**：全新 tokenizer，重构质量与可学习性全面提升。
  - **H3-Omni Transformer**：为任务泛化设计；放弃了 Hailuo-02 架构，针对多模态上下文引入后序列长度方差 3 倍化、理解与生成负载异构做了训练策略调整。
  - **In-Context Regeneration**：2K 输出不走传统独立超分模块，而是让 H3 基模型在上下文中重新生成自己的低分辨率输出（声称架构更一致 + 2K 质量更好）。
- **训练范式**：尽早融合多数据类型与任务（T2I、T2V、T2A、多镜头建模、image-to-image/video 编辑、audio-to-audio 编辑、音视频到音视频编辑），参考与编辑关系通过自然语言而非固定任务集表达。
- **2K 实现**：默认输出 768P，2K 通过 In-Context Regeneration 实现；也支持把已生成的 768P 视频"升级重生成"到 2K（Video Regeneration 任务）。
- **H3-Context-IR 任务**：H3 基模型在上下文中重新生成自己低分辨率输出的独立任务，定价按 token 计费。
- **失败/局限**（官方自述）：H3 仍有改进空间——多模态理解是高质量生成的基础，下一代 H 系列计划整合 M 系列理解能力；当前模型尺寸偏小，scaling 是明确路径；部分场景视觉细节仍需提升，未来推更高分辨率与更高视觉保真。完整技术报告"即将发布"。

## 定价 / 商业模式

来源：MiniMax 开放平台定价页（platform.minimax.io/docs/pricing/overview、/docs/guides/pricing-paygo），2026-08-01 抓取。

MiniMax 把计费拆为两条线：
- **API Pricing（按调用实时计费，面向企业）**：Pay-as-you-go、Audio Subscription、Video Packages
- **Subscription Plans（按月订阅配额，面向个人/小团队）**：Token Plan、Token Plan for Teams

**H3 视频生成定价（Pay-as-you-go，按秒计费）**

| 任务 | 规格 | 价格 |
|---|---|---|
| Video Generation | 2K | $0.13 / 秒 |
| Video Generation | 768P | $0.08 / 秒 |
| Video Regeneration（768P → 2K 升级重生成） | 2K 输出 | $0.05 / 秒 |

输入素材计费：音频免费；图像前 5 张免费，超出 $0.04/张（重生成任务 $0.025/张）；输入视频按视频时长 × 输出分辨率计费（2K $0.13/秒、768P $0.08/秒）。

**H3-Context-IR 任务定价**：输入 $0.90 / M tokens，输出 $3.60 / M tokens。

**LLM（M3）定价参考**：≤512k 输入 tokens，输入 $0.30/M、输出 $1.20/M、缓存读 $0.06/M（永久 50% off 后价格）；>512k 输入 tokens 价格翻倍。

**Legacy 视频模型（Hailuo 02 / 2.3 系列）**仍保留，按"每段视频"计价（如 $0.19/段 768P 6s、$0.56/段 768P 10s 等）。

**收入模式小结**：API 按秒/按 token 实时计费（企业）+ 视频套餐预付费（Hailuo packs，更低单价）+ 月度订阅 Token Plan（个人/小团队，配额每月重置）+ 企业 Credits 预付余额（同账号下 Subscription Key 复用 API 资源）。

- **Zac Zuo（Hunter，@zaczuo）开场贴**：H3 擅长把混合参考素材变成"接近成品的动态作品"；可在一次请求里混合 text/image/video/audio，再用自然语言告诉 H3 从每个参考里"借"什么（角色、镜头运动、声音、视觉风格）；面向商业创意工作，typography/motion/pacing/sound 协同；API 已上线，权重即将发布。

- **Shivarchan C**：担心"all-in-one"工具会沦为"什么都做但什么都不精"；问商用/品牌用例输出质量。
