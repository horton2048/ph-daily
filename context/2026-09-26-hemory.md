## 是做什么的（如实复述，不评价）

iOS / Android / Apple Watch 端始终在线监听周围语音，用 VAD 切出有人的"时刻"，本地做转写和说话人聚类（"David," "Mike"），把每段对话存成可搜索的个人记忆。再以本地 **MCP server** 的形式暴露 `search_memory` 等工具，让 Claude Code / Codex / Cursor / Gemini 等 AI agent 直接在上下文里拿到"昨天那次会议上 David 说了什么"这类自然语言查询结果。命名 = Hear + Memory。

## 解决什么问题（事实层面，不判断值不值得解）

- 知识工作者每天开大量会、聊大量事，"说过什么"远比"写过什么"多；Hemory 让 agent 可以反向查询这些未落地的口头信息。
- 让 AI 编程/办公 agent 拥有跨工具的「听觉上下文」，可以自动生成 PRD、半年总结、回看某次定价讨论。
- 据创始人 Yingqi 自述："我 1/2 到 2/3 的工作时间都在会议里"，Hemory 是为这种工作形态设计的被动日记。

## 怎么做的（技术原理/机制，事实层面）

- **运行方式**：手机/手表端麦克风持续监听 → VAD 判定有人说话才计入配额 → 本地 ASR 转写 → 按对话活动自动分段 → 说话人聚类打标签。
- **核心机制**：本地运行一个 MCP server（标准协议），对 AI agent 暴露 `search_memory` 之类的工具；安装方式为 `cursor mcp add hemory` / `codex mcp add hemory` / `claude mcp add hemory`。
- **失败/误报处理**：未检测到语音的时间不计入使用配额；可手动或定时（如 9 AM–6 PM 工作日）开启；支持一键关停。
- **差异化技术点**：把"始终在线监听"做成跨设备（手机+手表），并通过 MCP 把语音记忆直接喂给第三方 AI 客户端，而不是绑死自有聊天界面。
