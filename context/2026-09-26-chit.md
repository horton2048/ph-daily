## 是做什么的（如实复述，不评价）

Chit 是一款 macOS 菜单栏应用 + CLI 工具。它读取本地磁盘上 Claude Code 已经写好的 transcripts（路径 `~/.claude/projects`），把这些会话日志按"项目（repo）"分组、汇总成一份"日 receipt"——可以直接粘贴到 standup、timesheet、客户端更新里。形态是一个 777 KB 的 Mac app，也提供同名 CLI。

强调"本地"：二进制里不带网络代码、不用 Hammerspoon、不用 Python、不要账号。开机即用，没有任何上传/账号体系。

## 解决什么问题（事实层面，不判断值不值得解）

- **"上了一天 Claude Code，到晚上想不起来上午干了什么"** ——Dmitry Guzerchuk 评论原话（PH 评论）原文如此；Charles Brewer 也提到"结束一个高效 session 之后很难准确回忆到底完成了什么"。
- **写 standup / timesheet / 客户日报没素材** ——receipt 设计成一键复制（纯文本或 Markdown），可以直接贴进工作流。Adams Parker 提到会把 CLI 输出 pipe 进自己已有的 timesheet 流程。
- **保护隐私的"对老板/同事可分享的工作摘要"** ——只展示 Claude 生成的 session 标题或触碰过的文件名，**永不展示用户原始 prompt**。

## 怎么做的（技术原理/机制，事实层面）

- **数据源**：读取 `~/.claude/projects/` 下 Claude Code 已写入的 transcript 文件，**只读访问**，不会写回。
- **分组策略**：按 repo 分桶，"最忙的排前面"。Agent 的 worktree 自动折叠回父项目（不再单独成行）。
- **每行内容来源**：优先用 Claude Code 自己生成的 session 标题；否则用 session 内触碰过的文件名。**完整 prompt 只用来判断"这次会话算不算工作"，永远不被展示也不被存储**。
- **路径脱敏**：只显示文件名，不显示完整路径。
- **性能**：一次扫 2.7 GB 的 transcript 目录约 1 秒。
- **网络验证（maker 在 PH 发帖里贴出）**：
  - `$ nm -u Chit | grep -c URLSession → 0`
  - `$ otool -L Chit | grep -c CFNetwork → 0`
- **CLI 参数**：`chit --today`、`--date=YYYY-MM-DD`、`--from=YYYY-MM-DD --to=YYYY-MM-DD`、`--markdown`。
- **快捷键**：`⌥⌃⌘C`（Option + Control + Command + C）唤出/隐藏 app；菜单栏常驻，无 Dock 图标。
- **限制（maker 自己披露）**：无法把"在某个隐藏项目里敲的话"从另一个项目里筛掉——隐藏粒度是项目级，不是句子级。
