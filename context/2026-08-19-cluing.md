## 是做什么的（如实复述，不评价）

Cluing 自称 "AI 时代的知识层"：一个让团队和托管 AI agent 在同一上下文里协作的平台。它把各家前沿模型和 Claude Code 跑在 Cluing 自己的基础设施上，团队成员与 agent 共用一份"活的"上下文（live context），而非各自孤立的文档。

三个核心支柱：
1. **Host（托管）**：团队级的托管 agent——所有 AI 模型和 Claude Code 都在 Cluing 基础设施上运行；可一键把 agent 产出的网站、仪表盘、应用发布到自有域名并带安全 HTTPS。
2. **Collaborate（协作）**：不止文档，而是共享 live context、动态技能（dynamic skills）、带加密密钥的连接器（connectors）、任务，以及执行这些任务的 agent；整个团队和 AI 从同一个"大脑"工作。
3. **Capture（捕获）**：浏览任意来源时一键抓取洞察，保存时附带来源、高亮和自己的批注。支持 YouTube、Reddit、PDF、LinkedIn、X、Quora、Kindle 高亮、邮件、Newsletter、paulgraham.com 等。

## 解决什么问题（事实层面，不判断值不值得解）

- agent 能力变强后，瓶颈在协作与基础设施：单 agent 跑得动，但团队级共享上下文、共享技能、发布产出物缺统一层
- 知识散落在 Google Docs / 表格 / 笔记本 / 浏览器标签里，难以为 agent 提供完整上下文
- 给 AI 提供完整上下文很重要但此前缺合适方式（官网引用用户评价）

## 怎么做的（技术原理/机制，事实层面）

- **托管运行**：Claude Code 等在 Cluing 基础设施上运行（官网有 "Claude Code running on Cluing" 演示），非本地
- **一键发布**：构建 → 部署 → 签发证书 → 上自有域名，官网演示发布流程到 dashboard.yourdomain.com LIVE
- **加密连接器**：连接器（如 Google Analytics）的密钥保持加密，agent 调用时不暴露明文
- **动态技能**：技能可动态定义、基于上下文运行（如"Weekly Report Writer dynamic skill"）
- **捕获机制**：Chrome 扩展在浏览时一键保存，带来源 URL + 高亮 + 个人批注
- 技术栈/误报处理/检测模型：未查到
