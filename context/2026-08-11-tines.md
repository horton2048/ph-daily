## 是做什么的（如实复述，不评价）

Tines 3B 是 Tines 公司在 2026 年推出的新一代（官方称"下一代 Tines"）AI 原生自动化与 agent 运行平台。与原 Tines Stories（基于 8 种可视化 action 类型的 SOAR/工作流平台）不同，3B 走"代码优先（code-first）"路线：把 Stories 的多种 action 类型收敛为"只有代码"，平台围绕三个原语构建——**代码（code）、连接器（connectors）、数据存储（data storage）**。非工程师可用自然语言描述需求，由 AI 生成并交付生产级代码；同时平台从第一天起就内建治理与安全层（SSO、RBAC、审计、监控），把"员工已经在用 AI 像软件工程师一样构建、有没有公司许可都行"这件事纳入可控边界。

"secure environment for agents" 的具体能力（PH 页与官网描述）：

- **隔离执行**：代码在隔离环境运行，凭据受到保护。
- **凭据代理注入**：AI 永远看不到凭据，凭据在运行时由代理（proxy）注入，避免把密钥暴露给 LLM。
- **可审计与监控**：所有交付物从一个地方做审计与监控。
- **自然语言构建**：可从任意位置用 AI 构建 workflow。
- **隧道能力**：可隧道进入家庭网络或自托管服务，无需端口转发。
- **LLM 灵活切换**：可随策略演进切换 AI provider；企业可"自带模型（BYO model）"。
- **自治修复建议**：Tines 识别并建议对异常/潜在故障的修复，由用户决定是否上线。
- **AI SOC / AI 网关**：面向 SOC 的告警接入、分诊、修复与分析师路由；面向 IT 的部署治理网关；MCP 与 AI client 管理。

## 解决什么问题（事实层面，不判断值不值得解）

- **"野代码（wild code）"问题**：用 AI 快速构建但未受治理与监控的工作在组织内蔓延，制造隐性安全风险（创始人评论原话引用此概念）。
- **AI 脚本蔓延**：IT/安全团队面对员工各自用 LLM 写脚本无人统管的局面。
- **凭据泄露风险**：直接把 API key/secret 喂给 LLM 的常见反模式。
- **企业 SOAR/自动化场景**：原 Tines Stories 已服务 Reddit、Coinbase、Databricks、Snowflake、Dropbox、Pinterest、MongoDB、Sophos、Canva、McKesson 等，3B 把这套能力扩展到 AI agent 时代。
- **个人/家庭实验室**：创始人明确把"在家搭建 home lab 或个人 agent 的人"列为目标用户之一。

## 怎么做的（技术原理/机制，事实层面）

- **架构原语**：code + connectors + data storage 三类原语，替代 Stories 的 8 种 action 类型。
- **代码优先**：直接写代码而非拼装可视化节点；AI 协助从自然语言生成代码。
- **凭据保护机制**：凭据不进入 AI 上下文，由运行时 proxy 注入到执行环境。
- **隔离执行**：代码运行于隔离沙箱。
- **治理层**：SSO、RBAC、审计、监控自首日内置；定位上区分于消费级 AI coding 工具。
- **技术栈**（PH "Built with"）：React、Bun、AWS。
- **部署**：灵活托管选项，具体方式需联系销售。

## 定价 / 商业模式

- **Free Edition（Explore Edition）**：免费，3 个 live workflow，无限用户/空间/连接器，一次性 $50 AI 额度；定位为"无承诺试用 Tines 3B"。
- **付费版（联系销售）**：无限 workflow、灵活部署选项、BYO AI model；具体价格官网未公开。
- **Startup Program**：针对小型成长团队的重度折扣 Stories tenant（排除 MSP、咨询等服务型公司）。
- **两条产品线并存**：3B（新一代 AI 原生平台）与 Stories（原 SOAR 平台）。
