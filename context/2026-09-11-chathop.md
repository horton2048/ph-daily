## 是做什么的（如实复述，不评价）

Chrome 浏览器扩展。核心功能是把一个 AI 助手（ChatGPT、Claude、Gemini 等）里**正在进行中的对话**，连同上文和上下文，搬到另一个 AI 助手里去，**不需要重新解释背景**。

附带两个次要功能：
- 一键复制整个对话为纯文本或 Markdown
- 下载对话内容

## 解决什么问题（事实层面，不判断值不值得解）

- **多 AI 助手并用是常态**：用户同时使用 ChatGPT / Claude / Gemini 等多个 AI，但每个助手都从零起，没有"对话可携带"的能力
- **切换 AI 成本高**：换到另一个模型意味着重新输入完整 prompt 和上下文，决策、目标、背景全丢
- **对话沉淀需求**：用户想把 AI 对话复制/下载出来留档或搬到其他工具（Notion / Obsidian 等）

## 怎么做的（技术原理/机制，事实层面）

官网描述的三步流程：
1. **打开现有对话**——ChatHop 在用户已经工作的 AI 助手里运行（依赖 content script 注入）
2. **点击、选择、完成**——选择迁移理由，再选择目标 AI
3. **审阅、发送、继续**——对话内容被放进目标 AI 的输入框待用户审阅，**自动发送默认关闭**，必须用户手动确认

技术细节：
- 形态为 Chrome 扩展（content script 读取页面对话 DOM）
- 付费走 Stripe，扩展本身**不存用户账户**——免费层无需注册/密码/信用卡
- 隐私声明：只在用户主动触发迁移或复制时读取对话内容；对话文本**不发送到计费服务**；无广告、无画像、无聊天分析；不出售对话数据

## 关联信息 / 生态

- **与 Monica / MaxAI.me 的关系**：Monica 和 MaxAI.me 是「侧边栏聚合多模型」（一个面板同时调多个 AI），ChatHop 是「跨模型迁移对话」（把已发生的对话搬到另一个 AI）。两者方向不同，前者是并行使用，后者是连续使用
- **与 TypingMind 的关系**：TypingMind 是统一 chat UI（用户自带 API key 在一个界面调多个模型），ChatHop 是无 API key 桥接官方 AI 产品
- **与 HARPA AI 的关系**：HARPA AI 强在「网页内容 + AI」（浏览器自动化 + AI 阅读网页），ChatHop 聚焦对话迁移这条窄场景
