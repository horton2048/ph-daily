## 是做什么的（如实复述，不评价）
AIF 是面向 AI 编程代理的"本地预执行防火墙"——作为中间件位于编码代理与操作系统之间，对每一个 agent 想执行的动作（命令、文件编辑、工具调用、出站请求）做执行前语义评估，根据开发者意图和会话上下文判断放行或阻断，并保留本地审计日志。Harden 将其定位为开源前端流行背景下"agent 安全"的补位产品，强调"无需账号、无需 SaaS、所有判断与历史都在本地"。

## 解决什么问题（事实层面）
- 痛点 1（带数字/案例）：agent 误把凭证/密钥泄露到出站请求或仓库外写文件——trust 页面声明对 9 类策略单元 100% 覆盖率，97 个真实攻击 + 99 个良性对照上 precision/recall 各 100%，P99 决策延迟实测 70.2 ms。
- 痛点 2：agent 在长时间任务中漂移执行破坏性操作——预览版免费拦截 `rm -rf ../sibling`、`rm -rf /`、对默认分支 `git push --force origin main` 等。
- 痛点 3：用户被迫"逐条 approve agent 动作"——PH 上 Anurag S. 帖子概括为 "Before Harden: approve every action. After Harden: let it run."
- 目标场景：本地开发者用 Claude Code / Codex / Cursor / Gemini CLI / Kiro / OpenClaw / Hermes 跑长任务；企业团队需要在不联网/不让 agent 触碰敏感边界的前提下放权。

## 怎么做的（技术原理/机制）
- 运行方式：本地守护进程，监听回环 `127.0.0.1:47391`；决策存于 `~/.aif/aif.db`，无保留上限；提供 `aif configure` / `aif demo` / `aif show [--tui]` 命令行。
- 核心机制：8B 参数的后训练模型，对每个工具调用做语义级评估；策略单元覆盖 Bash/Python/Node/MCP 调用；决策结果分五类——Allow / Block / Ask / Redact / Log。
- 差异化技术点：
  - **fail-closed**：守护进程不可达或崩溃时，hook 阻断工具调用而非放行。
  - **凭据源覆盖**：凭证文件、环境变量、AWS key / PEM / GitHub token 等已知密钥格式都纳入源端扫描。
  - **遥测匿名化**：默认收集安装 ID + OS + 架构 + 决策计数器；不收集代码/命令/路径/prompt/secret；通过 `AIF_NO_TELEMETRY=1` opt-out；自动更新检查可通过 `AIF_DISABLE_AUTOUPDATER=1` 关闭。
  - **签名链**：release 用 Ed25519（minisign）签名，公钥已公开供审计。
  - **声明范围**：明确"疏忽型 agent"为保护对象，对抗性规避（41 个已知缺口）不在本版本保护范围。

## 定价 / 商业模式
- **免费层（个人开发者，永久免费）**：核心密钥流阻断（Bash / Python / Node / MCP 全覆盖）、block-and-steer、`aif configure` / `aif demo` / `aif show --tui` / 卸载、本地决策存储、SDK、无账号条款。trust.md 明确承诺："Core pre-execution secret-flow blocking on your machine is free forever."
- **"预览—当前免费"功能**：仓库外递归删除、对默认分支 force-push；trust.md 写明退出预览只能三选一（晋升免费层 / 转入付费层 / 停用），不会出现"clawback"收费。
- **企业版**：网站放 "Book a call"（Google Calendar 链接），具体 SKU/价格未公开。
- **商业护栏承诺**：不向个人开发者收取本地保护费用、不放时间炸弹、对本地保护不做用量计量、不"将隐私付费化"。
