## 是做什么的（如实复述，不评价）

Termexo 是一个**本地 Windows 原生工作台**，把 Claude Code 和 Codex 这两个 CLI 形态的 AI 编程 agent 统一收进一个桌面应用里管理。核心形态是**真实 PTY 终端的网格布局**：用户可以并排开多个 agent 会话，每个会话是独立的 PTY，不是模拟终端。它解决三件事——会话恢复（崩溃/重启后用 `claude --resume` / `codex resume` 恢复上下文+布局）、模型 profile 切换（不用重建环境变量）、agent 审批通知（agent 需要用户批准时主动提醒）。**本地优先，无需 Termexo 账号**。

## 解决什么问题（事实层面，不判断值不值得解）

- **多 agent 会话散落终端窗口**：开多个 Claude Code / Codex 会话时，终端窗口乱、切换累、布局不可恢复。
- **崩溃/重启丢上下文**：Windows 终端崩了或机器重启，agent 进程和对话上下文丢失，要重新讲"之前做到哪"。
- **API key / 环境变量切换繁琐**：在不同模型 provider 间切换要重建环境变量，易错且不安全。
- **agent 需审批时不知道**：agent 跑到需要用户确认的步骤会卡住，用户没及时看到就浪费时间空转。
- **目标场景**：Windows 上重度使用 Claude Code / Codex 做并行 AI 编程的开发者。

## 怎么做的（技术原理/机制，事实层面）

来源：PH 产品页 + 创始人评论区 + GitHub 仓库描述

- **原生 Windows，非 WSL**：agent 跑在原生 Windows 上，不是 WSL。评论区 Yuki_Code1 追问 WSL vs 原生 Windows 的路径翻译摩擦，创始人确认只做原生 Windows。
- **真实 PTY 终端网格**：自定义 grid 布局，每个会话是独立 PTY，不是模拟终端或 chat 框。
- **会话恢复机制**（创始人评论区详细说明）：崩溃/重启后 PTY 和 agent 进程已死，Termexo 启动新 PTY 并调用 CLI 原生 resume（`claude --resume` / `codex resume`）。**对话上下文、workspace、模型/profile 选择、布局会恢复；原始 scrollback 和 in-flight 操作不恢复**。创始人原话："fresh process plus restored native context, not process-level checkpointing"——即不是进程级快照，是"新进程+原上下文恢复"。
- **模型 Profile 隔离**：每个 Model Profile 有独立的 API key，存在 **Windows Credential Manager** 里，按 profile ID 索引。数据库里只存 credential reference，不存明文 key。创始人原话："credentials are isolated per Model Profile, not shared globally"。
- **agent 审批通知**：agent 需要用户批准时弹通知。评论区 Tizer Luo 称其为"killer feature"并问检测机制是 permission protocol hook 还是 PTY 输出解析——**创始人未在可见评论区正面回答**。
- **技术栈**：TypeScript（GitHub 语言标注），仓库描述 "AI Workspace Control Plane"。
- **本地优先**：无需 Termexo 账号，无需上云。
