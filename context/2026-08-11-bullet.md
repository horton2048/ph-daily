## 是做什么的（如实复述，不评价）

Bullet 是一款主打"快"的本地编码 agent，同时提供 macOS 桌面 App（.dmg，arm64）和 CLI（`npm install -g @trybullet/cli`，需 Node 18+）。官方描述其运行模式为"模型→工具→结果"的更紧凑循环，目前处于私有 beta，免费开放，允许用户自带 Claude Code / Codex 订阅、API key 或本地模型——官方称之为"free speed"（用现有订阅即可获得加速，无需另付费）。

核心机制三点：
1. **Route / Escalate（路由升级）**：按任务复杂度把请求分为 fast / deep / reason 三档，简单任务路由给快模型，只有"任务需要"时才升级到更强模型。
2. **Search / Acquire（定向检索）**：做相关性评分的定向代码搜索与文件读取（官网示例：`src/router.ts` 94.2、`src/auth.ts` 88.7），不做整库 embedding。
3. **Parallel Execution（并行执行）**：相互独立的工具调用并行执行；重复调用和卡住循环会被提前拦截。

桌面 App 与 CLI 共用同一套 router、tools 和 agent loop。无云端组件被披露，运行在本地。

## 解决什么问题（事实层面，不判断值不值得解）

- 官方称现有 Claude Code / Codex 等 agent "needlessly slow"（无谓地慢），创始人自述每天用 Claude Code，痛感现有 agent 机制太慢。
- 目标场景：日常软件工程任务（搜索代码库、读文件、执行操作），追求低延迟、高吞吐。
- 创始人 Alex Sima（CTO）在 PH 评论区提到一位 YC partner 鼓励他们"解决一个我们自己遇到的问题"。

## 怎么做的（技术原理/机制，事实层面）

- **路由**：模型/推理级别按 prompt 自动选择，fast/deep/reason 三档，具体模型标识未披露。
- **检索**：定向代码搜索 + 相关性评分文件匹配，避免整库 embedding 的延迟与上下文成本。
- **执行**：并行工具调用，重复调用与死循环拦截。
- **跑分**：用官方 SWE-bench Docker 评测 harness 评分，"containerized test execution scoring, not self grading"；策略为 K=1，每个实例一个候选 patch，无 best-of-N、无重排、无重试；500 实例全部完成，0 空 patch、0 harness 错误。生产 agent loop 跑在 GPT-5.6 Sol 上。
- **"30-60% faster" 依据**：该数字出自 PH tagline，官网 benchmark 页未直接给出"30-60%"这一具体百分比或对照方法学；benchmark 页只给出 Bullet 自身 SWE-bench Verified 的 95.8% / 119s 均值，以及对 Vals AI 上其他"complete agent systems"（Claude Opus 5 97.0%、GPT-5.6 Sol 96.2%、Claude Fable 5 95.0%，均用 mini-swe-agent harness）的引用对照——并注明 Bullet 用自家生产 harness，Vals 行用 mini-swe-agent，不属同 harness 严格对照。**"30-60% faster" 的具体测量方法学在已抓取页面上未查到，待补。**

## 关联信息 / 生态

- **SWE-bench Verified 跑分**：95.8%（479/500），均值 119s/任务，中位 104s，单实例成本 $0.73；2/3 任务 2 分钟内完成，全部在 7 分 1 秒内完成。
- **仓库级表现**：scikit-learn 32/32、pytest 19/19 满分；Django ~223/231（~96.5%）；astropy 18/22（Bullet 最难的仓）。共 21 处未解。
- **对照（Vals AI，非同 harness）**：Claude Opus 5 97.0%、GPT-5.6 Sol 96.2%、Claude Fable 5 95.0%，均用 mini-swe-agent。
- **当前版本**：v1.3.24。
- **竞品定位**：直接对标 Claude Code、Codex；生态关联 Cursor、Cline、mini-swe-agent。
