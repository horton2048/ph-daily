## 是做什么的（如实复述，不评价）

Resurf 把自己定位为 **"A Personal Context Library"（个人上下文库）**——一个可以"快速存、随时找、交给 AI 用"的本地化知识捕获应用。

形态上是一款**完全原生的 Swift 应用**，覆盖 macOS、iPhone、iPad 三大 Apple 平台，另有 Chrome 浏览器扩展。技术架构刻意绕开 Electron，所有数据**默认存在本地 `~/Library/Resurf`**，可选择性地通过用户自己的 iCloud 在多设备间同步——不需要注册任何 Resurf 账号。

核心使用场景是"捕获—整理—复用"三段：用户在任何应用里看到一个链接、一段文字、一张图、一段视频或音频、一个 PDF，都可以用全局快捷键 `⌘⇧C` 把它先扔进 Inbox，事后通过 **Spaces（项目）+ Tags（主题）+ Stacks（分组）** 来整理；将来需要时用 Spotlight-style 全局搜索（`⌘⇧Space`）找回来，或直接交给 AI——通过 **MCP（Model Context Protocol）** 或 **CLI** 把库内容暴露给 Claude 之类的外部 AI 工具，用户自备 API key（Bring Your Own AI）。

官网首页还列出多项能力：Quick Capture、Inbox First、Spaces & Tags、Visual Library、From Any App、Instant Search、Voice Memos（带 on-device 转写）、Highlight & Annotate、AI Summaries（opt-in）、Bring Your Own AI（opt-in）、Ask Your Library（opt-in）。

## 解决什么问题（事实层面，不判断值不值得解）

- **碎片化**：用户日常遇到的内容（文章链接 / 截图 / PDF / 推文 / YouTube / GitHub 仓库 / 代码片段 / 语音备忘）散落在多个 app 里，时间一长几乎不会回去看。创始人在 PH 发帖的原话：「My saved items became scattered across apps and I rarely came back to them.」
- **工具割裂**：笔记是一个 app、书签是一个 app、图片又是一个 app，要"重新找到"一件事需要在多个 app 之间切换。
- **AI 没有上下文**：通用 AI 助手能搜索公网但不能搜你私人的资料库。Resurf 想把"自己存过的东西"也变成 AI 可读的上下文。
- **隐私焦虑**：把私人笔记交给大厂的服务器会让人犹豫。Resurf 通过"数据全本地 + 可选私有 iCloud 同步"回避这一点。

## 怎么做的（技术原理/机制，事实层面）

- **运行方式**：纯原生 Swift 客户端，无 Electron；v2.0（2026-08-08）从非原生栈**完全重写**为 Swift。
- **存储路径**：macOS 下数据落在 `~/Library/Resurf`，用户可读写、可备份、可迁移。
- **搜索**：v2.0 起搜索后端切到 SQLite 全文本索引（changelog 原话：「Instant search rebuilt on SQLite full-text search」）。
- **同步**：用 Apple 自家的 iCloud 做**私有同步**——即数据走用户自己的 iCloud Drive 通道，不经过 Resurf 自己的服务器，因此 Resurf 后端理论上不持有用户内容。
- **AI 接入**：
  - 客户端内嵌一个"docked AI pane"，可用自己的 OpenAI / 其他 key 直接在 App 里问自己的库。
  - 对外通过 **MCP server** 和 **CLI** 把本地库暴露给外部 agent（Claude Code 等），相当于把 Resurf 当作 agent 的 long-term memory。
- **扩展面**：Mac / iPhone / iPad / Chrome 扩展 4 个入口，捕获快捷键统一为 `⌘⇧C`。
- **离线**：完全本地存储 → 离线可用；不依赖任何 Resurf 自己的后端服务。
