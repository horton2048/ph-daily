## 是做什么的（如实复述，不评价）

Atlaso 是一个**「AI 记忆层」（AI memory layer）**——为开发者常用的 AI 工具（Claude Code、Cursor、Codex、Claude Desktop、OpenCode、Antigravity，即将支持 ChatGPT、Meta AI）提供一块共享、持久、跨工具自动同步的记忆。连接一次之后，这些工具会在每次会话中自动「写入」（capture，捕获你在工作中的决定、注意点、偏好）并「读取」（recall，在下一条 prompt 前注入相关的历史记忆）。记忆存在用户的 Atlaso 账户里，而不在任何单一 App 内部（官网原话："memory lives with your account, not inside any single app"），所以在一个工具里学到的内容，另一个工具下次召回时能直接读到。

形态：免费账户 + 本机安装命令（`curl -fsSL https://atlaso.ai/install.sh | bash`）接线到各 AI 工具，配套 web dashboard 查看/管理记忆。不要求用户手动「归档/建档」——抓取是自动的。

## 解决什么问题（事实层面，不判断值不值得解）

- **跨工具重复解释上下文（re-explaining tax）**：创始人 Ashish Khandelwal 开场评论自述 "I was tired of re-explaining myself to every AI I used"——在 Claude Code 讲一遍项目背景，去 Cursor、Codex 又得重讲一遍。
- **会话结束即失忆**：Claude Code 官方连接器 README 原话 "Claude Code forgets everything the moment a session ends. Atlaso remembers"。现有 AI 每次会话「开机空白」（官网 Ambient Memory 文案 "Your AI wakes up blank every session"）。
- **记忆锁死在单一 App**：每个工具各存各的，信息不互通。Atlaso 的定位是「一块记忆跟着账号走，而不是被锁在某个应用里」。
- **目标场景**：多 AI 编码工具间的开发者工作流、项目决定与约定跨工具跟随、个人偏好（如 "I prefer tabs"）全局跟随。官网行业页另覆盖 Software & Engineering、Finance、Healthcare & Life Sciences、Legal、Research & Education、Sales & Support。

## 怎么做的（技术原理/机制，事实层面）

来源：官网首页 + 官网研究页 + GitHub 连接器 README + PH 创始人评论

- **三种连接方式**：Hooks（Claude Code/Cursor 等）、MCP server（mcp.atlaso.ai，任何支持 MCP 的工具可接）、Skill/plugin。Claude Code 连接器含 4 个 hook：`recall`（`UserPromptSubmit`，每条 prompt 前同步注入记忆）、`capture`（`Stop`，即时**本地**写入无网络，稍后同步）、`start`（`SessionStart`，与云端同步缓存，detached 不阻塞会话打开）、`end`（`SessionEnd`，flush 本会话记忆+拉取新内容）。
- **注入块**：recall 在模型看到 prompt 之前运行，注入块以 `=== Atlaso Memory ===` 为界、不含指令，由模型自行决定如何使用。Claude Code/Codex/OpenCode 每条 prompt 都召回；Cursor 每会话召回一次（创始人评论：「真正的乘数是 turns 而不是 memories」）。
- **检索机制**：keyword + semantic 混合检索（BM25 + embeddings，rank-fused），k=5，服务端硬上限 50 条；只注入相关性超过阈值（首页截图显示 "Below floor 0.5 — not injected"）的条目。搜索在服务端跑、检索路径上无 LLM，用户侧零 token 成本。中位记忆长度下注入块约 **650 tokens**（实测 934 条记忆的库，50/500/5,000 条记忆块大小恒定因为 k 固定）。
- **存储语义**：append-only。无 TTL、无剪枝——recency decay 被刻意关闭，因为会降权「旧而正确」的事实、损害 LongMemEval-S 准确率（创始人：「The store grows forever; what's bounded is what comes back, not what's kept」）。
- **两种作用域**：personal memory（跨工具跟随）+ per-project memory（锁定到单个 repo，同一 repo 换机器仍共享）。
- **Verdicts 机制**：记忆带判定（settled / contested / thin），支持 superseded（被取代）语义；官网宣称「contradictions flagged, superseded facts retired」。但**发布时点**上：读侧已排除被取代目标，写侧 deposit API 尚不暴露 `contradicts` 字段（创始人评论：「Small change, and it goes first」），且没有任何已发布连接器会触发 supersede 写入。
- **摄入零 LLM 调用**：与 mem0 默认在摄入时用 gpt-4o-mini 提取不同，Atlaso 写 deposit 时不调用 LLM（官方 benchmark 声明）。
- **密钥清洗**：capture 离开设备前先扫描并替换 secrets（API keys / tokens / passwords / credentialed URLs，替换为 `[REDACTED:…]` 占位符），服务端「到达时再清洗一次」作第二道网。客户端+服务端双重。
- **fail-open**：hook 出错时静默 no-op，工具照常运行（"If Atlaso ever hits an error it fails silently"）。
- **同步模型**：每账户一个 store，带 seq number 增量同步（如 "sync · seq 1042 → 1043"）。
- **Ambient Memory（Pro 实验功能）**：会话开始时、用户输入前注入「THE BACK OF YOUR MIND」四信号块——自上次以来变化、你反复回来做的事、未决矛盾、方向。规则「it orients, it never invents」；模型被指示把该块当作 orientation 而非事实，行动前须与用户确认。
- **后台 enrich（Pro）**：夜间后台 worker 把 raw captures 蒸馏为结构化记忆（tagged / graded / deduped）。
- **免费版隐私**：免费版记忆内容「绝不发给任何 LLM」；全版本不训练、不售卖。
- **GitHub**：org `atlaso-labs`（2026-06-26 创建）有 7 个公开 repo，均为连接器/CLI/MCP（claude-code、cursor、codex、antigravity、cli、mcp、.github，0 stars，无核心引擎代码，引擎在服务端）。

## 定价 / 商业模式

来源：atlaso.ai/pricing（2026-08-05 抓取）

- **Free（免费）**：1 device + 1 active tool；自动 capture & recall；personal + per-project memory；云端同步 + web dashboard；无限 memories；secrets scrubbed。免费版记忆内容绝不发给任何 LLM。
- **Pro $10/月**：无限设备与工具、单一共享记忆、Ambient Memory、夜间后台 enrichment、Ask your memory、JSON 导出。
- **Build $25/月**：Pro 全部 + Memory API（每个终端用户私有隔离记忆、项目 API key server-to-server、可连接任意软件/硬件如 web、ESP32、机器人、按项目使用仪表盘）。fair-use 无按调用计费，超出联系销售另议。
- **无团队版**（官网 pricing 无团队档位，创始人评论中建议团队用户暂用共享付费账号）。
- 月度计费、随时取消；**无年度计划**（"planned"）；**无试用**（免费版即试用）。降级不删记忆，额外设备 5 天宽限。EU/UK 客户保留 14 天退款权。
- 全版本：加密传输与静态存储、不训练不售卖记忆、每记忆可删除并全设备同步；账户级删除需邮件 support@atlaso.ai 人工处理（无自助）。

## 评论区反馈（事实摘录，不评价）

- **Martín Herrán**：称赞 "thin/settled/contested/superseded" 记忆区分；问推断出的记忆如何不覆盖 repo/docs/更新决定中的真相，是否有完全本地/自托管模式。→ 创始人回复：repo 可检查而记忆不可，所以文件里的真相优先；新决定经 MCP 告知 AI，AI 找到旧记忆、移除并存新的；但不会捕获从未标记的逆转。自托管今天没有。secrets 在设备端剥离后才发送、到达再剥一层；不读记忆、不训练。
- **Asad M.**：质疑「orients, never invents」是自跑 benchmark 营销；指三会话前已被逆转的决定仍以 settled 注入、读起来「和正确的一样自信」；问记忆如何死亡、能否一键 kill。→ 创始人回复：承认 benchmark 是自家跑，但辩护方法（同一 reader、四裁判含 mem0 自己的 judge prompt、归一化答案）；主动公开 LoCoMo 输 11.5 分；承认 supersede 机制存在但无已发布连接器触发它，旧记忆仍活着且和新记忆看起来相同；Claude Code/Codex 里 recall 块进模型不进终端，kill 需去 dashboard——「That's a real gap and I'd rather fix it than argue it」。问是否想要每行 id + 一条命令 kill。
- **Ridhwik Vinod**：称赞公开败绩的 benchmark；问团队记忆（品牌规则、所有权、决定属于团队而非个人，想推广到 36 人）。→ 创始人回复：Atlaso 目前「是一人跨工具的记忆」，按用户隔离，无共享层、无角色、无归因。诚实变通：付费账户支持 100 设备，可共用一个账号获得共享记忆，但 recall 按账户限速且按单人规模设计，Claude Code 每条 prompt 拉记忆，十来人并发会撞限流；无归因则「一个人的偏好变成所有人的，且任何人都能删任何东西」。建议先 4–5 人试点；邀请邮件 co-design 团队账户。
- **You Li**：两个问题：① tidy-up——session 40 与 session 4 矛盾时是覆盖/版本化/表面化？有没有标记 stale？② token 成本——选择性检索还是全库？500 vs 50 记忆的每会话开销？→ 创始人回复：token 是选择性的（top-k 混合检索，k=5，服务端硬上限 50）；中位记忆长度注入块约 650 tokens，50/500/5000 条记忆块大小恒定；搜索服务端跑、无 LLM、用户零成本；tidy-up「三者皆非」——两行都存、都活着、无标记矛盾，append-only；引擎有 typed dispute/supersede 语义但无连接器写入；无 TTL 无剪枝，recency decay 刻意关闭。
- **You Li（追问）**：称 650-token 是「本页最有用的数字」；指旧事实和其修正对 BM25+embeddings 几乎不可分、都会进 k=5，agent 拿到两条矛盾事实而无法标记新旧——「arguably worse than returning neither」；建议 write-time 冲突标记。→ 创始人回复：「You've got it right, and the answer to 'what decides' is: nothing good」——consume 端不触发 dispute，排序键恒定、纯相似度无 tiebreak，赢家「effectively arbitrary」，通常两条都在 k=5；称这是「the sharpest description of the failure anyone's given me」；roadmap：read 侧已排除被取代目标，缺的是 write 路径（deposit API 不暴露 contradicts 字段），「Small change, and it goes first」；赞同 write-time flag 是正确 interim 方案（记忆写入时已嵌入，nearest-neighbor 几乎免费）；「Automatic detection can come later and be wrong quietly. A flag can only be wrong loudly.」接受 You Li 的写稿提议。
- **You Li（结构回复）**：「I don't rank, I scope」——自己的实现是 MEMORY.md（活）+ ARCHIVE.md（被取代内容，不在检索路径）+ 路由映射表（任务类型 → 工作站），路由优先、搜索第二；「Similarity never runs across the whole store」；问 Atlaso 有没有 scope 概念（per project/tool/workspace）还是每用户一个全局 store。
- **Hannes**：问与 Supermemory 的区别（尤其 Claude Code/Cursor 开发流），现有 Supermemory 记忆能否导入。→ 创始人回复：Supermemory「largely a platform you build with」（API/SDK/connectors 导入文档知识源）；Atlaso 装进工具本身（插件），自动从会话捕获决定/偏好、下条 prompt 注入相关条目，无 filing、无 recall 工具；跨工具是设计使然——Claude Code 里的修正 Cursor 下次召回就能读到；无需 import，Atlaso 暴露 MCP server，把导出粘贴进任一连接工具说「save each of these」即可（约 60 记忆/分钟）；也可把导出发给创始人代为加载。Hannes 回复称 Cursor↔Claude Code 免手同步「was literally one of my biggest pain points」，计划试用 MCP 流程。
- **Cyrill**：问 per-project vs global 如何应对两个技术相似但约定不同的项目。→ 创始人回复：「Honestly that's the whole reason this exists」——每个 repo 独立记忆，同栈项目互不见；「I prefer tabs」是你、「The build uses X」是 repo；模糊事实留在 repo 侧，因为「a fact turning up where it doesn't belong is worse than a fact you have to say twice」。
- **Jack Lin**：问相关 repos 能否共享一个记忆空间而不全局化。→ 创始人回复：今天不行，只有两层（个人或单 repo）；承认这是「a real gap rather than an edge case」，命名 repo 组形态容易建（scoping 机制已存在）；同时承认反向缺陷——monorepo 内带 package.json 的子包会被当成独立项目而非继承 repo。
