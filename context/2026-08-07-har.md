## 是做什么的（如实复述，不评价）

HAR 是一个开源、agent-agnostic 的多 agent 编码工作流框架，形态包括 CLI 和 MCP server。它把一个 repo 变成可被多个 coding agents 并行处理的隔离环境，并提供 deterministic validation gates、verifiable proof 和 observability。

它可与 Claude Code、Cursor、Codex 或任何 MCP agent 搭配使用。核心思路是把 repo 的运行、验证、隔离、证据记录写成一个 committed contract，而不是散落在 README、CLAUDE.md、Cursor rules 和 CI yaml 里。

## 解决什么问题（事实层面，不判断值不值得解）

- Maker Antoine Frau 在 PH 自述：单个 coding agent 在 repo 里工作很容易，但多个 agent 并行且仍可信会遇到一组问题。
- 公开材料列出的问题包括：没有标准方式运行/验证 repo；多个 agent 共享 dev server、database、ports、git state 时互相碰撞；人类仍要重新验证 agent 改动；vendor sandbox lock-in；手写脚本随栈变化而腐烂。
- HAR 目标是让每个 agent 有自己的 worktree、branch、ports、database，并把验证结果绑定到通过验证的 exact code/tree hash。
- Reviewer 看 logs、artifacts 和 validated tree hash，而不是只信 agent 的自述。

## 怎么做的（技术原理/机制，事实层面）

- CLI/MCP：安装命令为 `npm install -g @osfactory/har`；README 示例包含 `har env init`、`har env launch 1`、`har env verify 1 --full`。
- Isolation：每个 agent slot 得到独立 git worktree、branch、ports 和必要时独立 database，主 checkout 不被共享修改。
- Deterministic verification：项目真实 checks 通过固定 pipeline 运行，full verification 会捕获当时 codebase state，使 pass 与 exact code 绑定。
- Commit gate / proof：每次 run 留 logs、artifacts、validated tree hash；未验证 tree 不能 landing（具体 gate 配置需看 docs）。
- Mission Control：本地 dashboard 展示 repositories、worktrees、runs、validations、artifacts。
- Plugins：README 提到 Playwright、RocketSim 等 plugin 可扩展 verification stages。

## 关联信息 / 生态

- HAR 处在 agentic coding 基础设施层，服务 Claude Code、Cursor、Codex 等 agent，而不是直接生成代码。
- 与 Conductor/Superset 的“并行开很多 agents”相比，它重点放在 repo-level contract、验证证据和隔离运行环境。
- 与 CI 不同，它把本地多 agent 执行前后的 launch/verify/teardown 也纳入统一 harness。
- 相关产品包括 Warp、Codex、Conductor、Google Antigravity、Superset、Claude Code。
