## 是做什么的（如实复述，不评价）

一个面向 GTM / 营销团队的**实时网页数据平台**：聚合 650+ 数据源、3500+ 端点，通过 MCP（Model Context Protocol）或 REST API，让 AI agent 在对话里直接拿到**类型化（typed）**的企业、人员、职位、邮箱、帖子、价格、新闻等数据。

不是预先缓存的历史数据，而是**请求时实时从源头拉取**；返回的不是文档/HTML，而是结构化字段。能穿透登录墙、覆盖 page-reader 抓不到的源；端点"自愈"——站点改版或封禁时路由会自动绕到其它源。

用法分三步：连接（MCP server 接进 Claude/Cursor/ChatGPT，或用 REST API）→ 提问（自然语言写需求，比如"找欧洲种子轮 fintech 的 growth head"）→ 拿到 typed 结果（对话里、表格里、CRM 里）。

## 解决什么问题（事实层面，不判断值不值得解）

- **B2B 数据调用方式过时**：Apollo / ZoomInfo / Clearbit 给的是 UI + 导出 CSV，要先把数据下载下来再交给下游工具，agent 时代这条路走不通
- **浏览器代理的 token/时间税**：用 browser agent（TinyFish 类）跑"500 家公司按 ICP"意味着 500 次页面导航；Anysite 把这件事压成 1 次查询
- **传统爬虫返 HTML 浪费 context**：把整页 markdown 塞进 agent context 是普遍做法；Anysite 直接返 typed JSON，agent 只用处理结构化字段
- **多源整合**：单源（领英、领英群组、地图、电商、新闻）覆盖盲区大；聚合多源靠用户自己拼装

## 怎么做的（技术原理 / 机制，事实层面）

- **数据层**：650+ 源，3500+ typed endpoints；每源维护结构化映射（不是 OCR 后再正则）
- **接入层**：
  - MCP server（`anysite-mcp-server`，MIT，63 stars）—— 提供给 Claude Code / Cursor / ChatGPT / Codex / OpenCode 等
  - REST API（统一 auth header，返 typed profile）
  - CLI（`anysite-cli`，Python，MIT）—— 控制抓取、分析、入库
  - n8n 节点（`n8n-nodes-anysite`，TypeScript，MIT）
- **缓存 + 分页机制**（PH 评论中 Dmitrii 解释）：查询返回**首页 + 一个 cache key**，agent 想翻页或过滤时用 cache key 在本地分页/过滤，不再回源抓——既压住 context window，也压住 credit 消耗
- **自愈路由**：源站改版/封禁时，端点自动切换到备用源（具体路由策略未公开）
- **穿透登录墙**：能访问需要登录的源（具体哪些源支持未公开）
- **覆盖域**：社交媒体、电商、新闻、金融、地图、代码（官网列举）
- **关联产品 MCP server**：GitHub 还有 `GDELT-mcp`（全球事件数据库 GDELT 的 MCP 包装）和 fork 自 Docker `mcp-registry` 的 fork 仓
