## 是做什么的（如实复述，不评价）

Rindler 是面向企业团队的网页自动化 agent。用户用自然语言描述任务，它登录真实网站、执行过去由人工在门户网站里完成的重复操作，并返回结构化数据或执行结果。典型任务包括供应商/政府/医疗/保险/HR/银行/旅行/地产等外部门户上的查找、录入、下载、核对和定时执行。

产品强调自己不是通用脚本录制器，而是先理解目标网站，构建站点地图，再让运行时 agent 复用这些地图完成任务。

## 解决什么问题（事实层面，不判断值不值得解）

- 很多企业流程卡在第三方 Web portal，没有 API 或 API 覆盖不完整，仍需要员工登录网页手工操作。
- 通用浏览器 agent 在登录、MFA、页面变化、动态表单和失败恢复上不稳定；Rindler 官方将这些归为企业可用性的主要障碍。
- 使用场景包括采购/AP 门户、政府和法院系统、医疗/保险平台、HR/招聘系统、银行/贷款、商务旅行与房地产后台。
- 官网/公开材料称，相比 browser-use，Rindler 可做到 4x faster、3x cheaper、2x fewer failed tasks；这是官方对比声明，未查到第三方 benchmark。

## 怎么做的（技术原理/机制，事实层面）

- Ingest + mapper：先读取站点并构建 site map，agent fleet 对地图进行修正，地图再与 live site 校验。
- 运行时复用：执行任务时不完全从零探索网页，而是复用已验证 site map，以降低失败率和成本。
- 账号与 MFA：官网材料提到 managed browser MFA；credentials 加密保存，按 user/site 隔离，不暴露给模型。
- 稳定性检查：公开资料提到 daily capability checks，用于确认目标网站能力是否仍可用。
- 输出：任务完成后返回结构化数据或操作结果；是否提供 API、Webhook、审计日志、权限模型细节，公开材料未完全披露。

## 定价 / 商业模式

官网公开定价：Starter $100/月，含 100 runs、1 个 login-gated site、7-day trial；Teams $1,000/月，含 1,000 runs、10 个 sites、scheduling 与 team workspace；Enterprise custom。公开资料还显示 $1 per completed run，failed/no result 不收费。

## 关联信息 / 生态

- Rindler 位于浏览器 agent、RPA 和无 API 集成之间：比脚本录制更偏 agent，比传统 RPA 更强调自然语言和站点地图。
- 相关产品/方向包括 browser-use、Bardeen、Zapier、UiPath、Robocorp、browser automation MCP。
- 其商业边界更偏 B2B operations 自动化，而不是个人浏览器助手。
