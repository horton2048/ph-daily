## 是做什么的（如实复述，不评价）

SyncStaq 把 Stripe 账单数据同步到 Google Sheets，分到不同结构化标签页：charges、invoices、invoice line items、customers、subscriptions、payouts、disputes。**核心差异**：按 Stripe **事件流**（event stream）同步，而非按 creation date 轮询——退款、订阅变更、争议发生后，原行被更新而非追加新行。

## 解决什么问题

- **轮询同步会过期**：现有 Stripe→Sheets 工具按 creation date 轮询，refund/dispute/subscription update 发生在原交易之后，原数据不更新就过期
- **数据散落**：账单字段散在 Stripe 后台，财务/运营要导出整理才能用
- **变更追溯**：3 月交易在 8 月被争议，原行被静默更新可能改写已上报董事会的数据

## 怎么做的

来源：PH 产品页 + 创始人评论区

- **事件流同步**：从 Stripe 事件流订阅更新，而非按创建日期轮询
- **分标签页结构化**：charges/invoices/line items/customers/subscriptions/payouts/disputes 各一页
- **更新原行**（mutate-in-place）：变更发生时更新原行而非追加新行
- **只读 Stripe 权限**：最小化 Stripe API scope
- **每小时同步**：hourly 同步频率
- **Sheet 在用户 Drive**：Sheet 存用户自己 Google Drive，不在 SyncStaq 侧

## 评论区反馈

- **Rabnoor Singh**（关键质疑）：mutate-in-place 行为——3 月交易 8 月争议时，原行被静默更新，"quietly rewrites a number someone already reported to a board"。建议 Sheet 标注 "Stripe only"。
- **Varun Krishna**：附议 mutation 顾虑，建议加 `last_updated` 或 `status_changed_at` 列标记追溯变更。认为佣金/分成 revenue-share 用例比单纯同步层"更有防御性"。
- **Raffay Sajjad**：对同时用 Stripe + Apple/Google IAP 的团队，"Stripe-only view 是真实收入的三分之一"。
- **Artem Fedorovich**：问同步是 reconcile 历史行还是只 append 新数据。Matt 确认更新原行。
- **Valeria**：问 webhook vs polling 和最小 Stripe token scope。Matt：组合多种来源，只读权限。
