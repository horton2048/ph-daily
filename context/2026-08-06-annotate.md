## 是做什么的（如实复述，不评价）

Annotate 是一个 macOS（Apple Silicon）本地录屏工具，把录屏转成 AI 编码 agent 能直接读取的"任务简报"。官网 tagline 是"Don't type, just point and speak"（别打字，指着说）。使用流程三步：1) 录屏——可只录一个窗口，也可一次录全部显示器；2) 指着说——在界面元素上画标注（笔、矩形、文字），用语音说出你想改什么；3) 交接——把会话直接交给 Cursor、Claude 或 Codex 等 agent。产品宣称本地运行、免费、无需登录、不上传录制内容。它随 app 附带一个本地 MCP server（`annotate-session`），agent 通过它按"关键帧 + 语音转写"读取录屏，而不是把整段视频当输入。

## 解决什么问题（事实层面，不判断值不值得解）

- 长文字 prompt 描述不清导致 agent 猜错：maker 开篇评论称"我写了很长很细的 prompt 想获得更好结果，agent 还是猜错"。
- 截图表达不了动态：maker 称"截图太静态，抓不住动作、表单输入流程、实时 UI 反馈"。
- 减少 token 消耗：agent 通过本地 MCP 读取关键帧 + 语音转写，而不是喂整段视频（官网/MCP 页："frames and speech, not a giant video dump"）。
- 目标场景：给 coding agent 描述 bug 复现步骤、UI 变更需求、表单操作流程等"动起来才能说清"的任务。

## 怎么做的（技术原理/机制，事实层面）

- 录制交互：`Ctrl+Shift+R` 开始/结束录制；`Ctrl+1/2` 切换画图工具；按住 Shift 让画的内容永久留在屏幕上。
- 语音与画面时间对齐：官网称"Your voice is transcribed and lined up with what was on screen when you said it"（你的语音被转写并与说话时的屏幕内容对齐）。
- 会话 = 文件夹：录屏会话是 agent 可读的文件夹结构，而非静态截图堆。
- MCP 传输：app 内置本地 stdio MCP server `annotate-session`，配置到 Cursor / Claude Desktop / Claude Code / Codex；提供 `list_sessions`、`get_timeline`、frames/transcript 搜索等工具；agent 先调 `get_timeline` 再用搜索/帧/转写工具。
- 环境要求：Annotate app 已安装且至少启动过一次（MCP bundle 随 app 创建）；本机有 Node.js 在 PATH；默认 MCP 入口 `~/Library/Application Support/Annotate/mcp/annotate-session/index.js`。
- 多显示器：一次录制可同时包含"app 在一个屏、编辑器在另一个屏"。
- 本地优先：官网反复声明"Stays on your Mac. Never uploaded."（留在 Mac 上、永不上传），"Frames and transcripts live on your machine... nothing leaves the device."。
- 版本：当前下载包为 Annotate-0.1.13-arm64.dmg。
- 技术栈（PH "Built With"）：Cursor、Vercel、PostHog。
