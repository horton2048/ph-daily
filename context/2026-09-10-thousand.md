## 是做什么的（如实复述，不评价）

Thousand 是一个**真实的 git 仓库**作为底层存储的团队文档平台：一个 workspace = 一个 git 仓库，文档就是仓库里的 markdown 文件。每个文件夹可以单独设访问规则（editor / commenter / reader / 隐藏），同一份文件人类用 web 文档编辑器读、AI agent 用 git clone + MCP/HTTP API 读——读到的字节完全相同，没有"导出"过程。

文档旁边可以挂评论（评论本身也是 markdown，存为 `<folder>/.comments/<name>.md` sidecar 跟着仓库走，git clone 出去仍然能读）。可以镜像别的仓库的文件夹进来（read-only，源仓库权威）。支持 Excalidraw 画布、CSV 表格、Office/PDF 作为仓库里的文件存在，原地编辑，按同样规则管控。

Agent 是 workspace 的一等成员：自己一个名字、自己一套文件夹、用一个有有效期（1–366 天）的 token 登录；走 git clone 工作（Claude Code / Codex / Cursor 直接 clone 仓库编辑提交），或走 MCP server 一条命令接入，或走 HTTP API + 个人 token。

## 解决什么问题（事实层面，不判断值不值得解）

- **"Notion vs 仓库"的二选一**：传统文档工具（Notion / Google Docs / Confluence）存专有格式、API 拉出来给 agent 用经常缺结构；git 仓库天然适合 agent 但天然全公开，一个夹子要私有就回到 Notion。Thousand 想消除这个 trade
- **AI agent 看不到的部分 ≠ 不可见**：很多文档工具 agent 看不到的内容其实"在那里"（被权限层挡住），agent 会忽略或猜测。Thousand 反过来——sealed folder **在物理上就不存在于受限 clone 里**，连 git 历史都没有，agent 不会假装自己看到过
- **团队协作里非技术成员不会 git**：他们用 web 文档编辑器写，存盘自动生成命名 commit；agent 用 git clone / API 写，两者落在同一个 commit 历史
- **外部分享文件**：任何文档可以生成"链接分享"给没账号的人，主端可以撤销、有访问次数统计
- **写之前不知道谁能看**：每个共享文件夹自带 `.thousand-access.md` 自动生成的 audience note（谁能看到、tier 是什么），agent 在写敏感内容前必读
- **多家远端仓库不打架**：Thousand 只是仓库的**一个额外 remote**，可以与 GitHub / GitLab 同存并跑
- **搜索覆盖 Office/PDF**：PPT/PDF 不止按文件名搜，按文件里的内容搜（提到"unit economics"就同时召回 `roadmap.pptx slide 4` 和 `pitch.pdf page 2`）

## 怎么做的（技术原理/机制，事实层面）

- **存储层 = 真 git**：每个 workspace 是一个独立 git 仓库，路径就是文件夹路径，git clone 出来是标准仓库
  - sealed folder 在受限 clone 里**根本不存在**（文件、历史、对象都不存在），靠构造而不是访问位
  - 服务端规则：一次提交只能覆盖一个顶层文件夹；`main` 分支唯一服务；强制推送被拒；platform-owned 文件（`.thousand-access.md`、`.comments/`、`.thousand/`）不允许编辑或创建
  - 大文件：单文件 25 MB 上限、整仓库 1 GB 上限；走 `git.usethousand.com`（直连）推送无代理；走主域有 CDN 代理会卡 100 MB
- **接入协议三选一**：
  - **MCP**：`claude mcp add --transport http thousand https://<host>/mcp`，第一次用弹浏览器登录，工具集包括 `workspace_info / list_documents / search / read_document / write_document / diff_document / comment / delete_comment / audience / check_access / grant_access / connect_source / create_workspace`
  - **Git over HTTPS**：`git clone https://thousand:<token>@<host>/git/<workspace>.git`，跟普通仓库一样 pull/commit/push
  - **HTTP API + 个人 token**（token 形如 `td_…`，从 `/tokens` 页面铸出来或个人走 device sign-in 流程：`POST /api/device/start` → `POST /api/device/poll`）：
    - `GET /api/agent/read?key=&path=`（读文件+评论+HEAD+base hash）
    - `POST /api/agent/edit`（带 `base` 防并发覆盖；服务端判断"live"还是"isolated"）
    - `GET /api/agent/diff?key=&path=&since=<sha>`（未提交草稿 vs HEAD 或某 commit 之后）
    - `GET /api/agent/audience?key=&path=`、`POST /api/agent/comment`、`POST /api/agent/access`
    - `POST /api/agent/sources`（连接外部仓库镜像）、`POST /api/agent/workspaces/new`（开新工作区）
- **写入模式（agent 编辑时服务端决定）**：
  - `live`：立刻落到共享 tree，无人编辑时空闲 ~20 分钟自动 `[auto]` checkpoint
  - `isolated`：落到一个私有分支，对人不可见，直到人去 `/proposals` 合并
  - 切换阈值默认：> 8000 changed bytes 或跨 > 2 个文件 → 自动 isolated（folder 级策略可调），每次响应都返回 `delta_bytes` + `isolates_over` + `why`
- **路径级 ACL**：一个有序规则列表，first match wins，默认 deny
  - tier：`editor`（读+写）/ `commenter`（读+评论，写表面只有 comment endpoint）/ `reader`（读）/ `owner`（管规则）
  - 文档级 grant 可覆盖文件夹规则；`"days": 30` 可设临时 grant，到期自动失效
  - 评论权限继承：commenter 的写表面就是 comment endpoint，editor 可分享自己的可写层（最高不超过自己 tier）
- **Mirror / Sync**：连接外部仓库（GitHub / GitLab），把一个文件夹镜像到 workspace 内的目标路径，**只读**，源仓库权威；服务端**约每分钟**拉一次；私有源仓库需要只读 token（GitHub fine-grained PAT scoped to one repo + Contents read-only + expiry；GitLab project deploy token + `read_repository`），token 服务端存哈希，永不回显
- **评论 sidecar**：`gtm/verdict.md` 的评论存在 `gtm/.comments/verdict.md` 里——平台拥有，不让 git 改，clone 出去仍然带评论
- **Reconciliation（整理）**：owner 在文件夹页点 "tidy"，模型找重复/过期/矛盾/孤儿，**只生成 proposal 分支**让人合并；矛盾只会标记，不替人决定哪个事实为真；git 历史保留每次删除可逆
- **搜索**：内置白名单扩展（文档+资产），不在白名单里的（如 `src/`）同步进来但不展示
- **渲染**：Excalidraw 文件 → 画布编辑器；CSV → 表格；Office / PDF → 浏览器内嵌并可全文搜索
- **架构事实**（来自 security 页）：HTTPS 全程；Google OAuth 单点登录、零自管密码；token 哈希存储；公开分享链接 opt-in、可撤销、可过期；**支持自托管**

## 关联信息 / 生态

- **替代关系**：定位把"Notion 的体验 + git 仓库的 agent 友好 + 真实的细粒度权限"三者拼起来；明确点名要替换的痛点是"Notion-style 工具 + GitHub Markdown 双轨"（Founder PH 评论原文："many people are still juggling GDrive and Git-based Markdown for their day-to-day documentation"）
- **与 Notion / Google Docs / Confluence**：那些存专有格式、API 拉出来结构不全；Thousand 直接存 markdown，agent 拿来就用
- **与 GitBook / Outline / Slab**：同样是文档工具，差异是 Thousand 把 git clone 提到一等公民、ACL 是路径级不是页面级、agent 接入是协议级（MCP / git / API 三种）
- **与 Obsidian（Git 插件方案）**：Obsidian 是本地优先，团队协作需要外部加插件；Thousand 反过来——托管 + git remote 出口，git 永远是可走出口不是入口
- **AI agent 适配**：MCP server 一行接入（claude mcp add / codex mcp add）；token 必有过期；profile card 显示这个 token 能看到什么；agent 的 grant 跟人同套规则（没有"agent 特权"）
- **同步来源**：从 GitHub / GitLab / 任意 git 仓库的 `docs/` 或 `context/` 之类文件夹镜像进来；约 1 分钟拉一次
- **第三方依赖**（来自 privacy 页）：Google（OAuth 登录 + Fonts CDN）、AWS（us-east-2 俄亥俄，存工作区数据）；**无第三方分析、无广告、无追踪 cookie**——只用一个签名 cookie 保持登录
- **媒体露出**：未在常规科技媒体看到独立报道；PH 是主要曝光通道
