## 是做什么的（如实复述，不评价）

AirBuddy 是 macOS 菜单栏外设管理应用，把 iOS 上"打开 AirPods 盖子弹出电池弹窗"的体验搬到 Mac，并扩展到 Beats、Magic Mouse/Keyboard/Trackpad、第三方蓝牙耳机、鼠标、键盘、手柄等设备。除了显示电量与连接状态，第 3 代主打四块能力：

1. **设备电量与状态监控**：菜单栏 / 弹窗 / widget 展示多设备电量、连接状态、低电提醒。
2. **音频控制与 now-playing 集成**：在 Mac 上控制 AirPods / Beats 的 ANC 模式、媒体播放；第 3 代加深了媒体集成。
3. **Magic Handoff（外设在 Mac 间切换）**：把同一套蓝牙外设在两台 Mac 之间快速切换，无需走系统蓝牙菜单的"断开-重新配对"流程，底层仍走解绑/重配对，但 AirBuddy 自动化包装为一步操作，声称通常 < 3 秒完成。
4. **自动化与定制**：设备连接时自动启动 app、自定义提示音、Shortcuts 动作、菜单栏 widget 定制等。

官网以一句标语概括："See batteries, connect AirPods, control what's playing, and move peripherals between Macs—all without leaving what you're doing."

## 解决什么问题（事实层面，不判断值不值得解）

- macOS 原生对外设电量/连接状态的可视化弱：原生蓝牙菜单只显示已连接设备，AirPods 电量需开控制中心或 widget，无 iOS 弹窗式体验。
- 多 Mac 用户切换外设麻烦：评论者 Manav Sehgal 称当前系统蓝牙菜单"舞蹈"繁琐；Omri Ben-Shoham 询问切换速度，得到"通常 < 3 秒"的回复。
- now-playing 控制分散：macOS 原生 now-playing 在锁屏/控制中心显示，但 Apple 在 macOS Tahoe 周期收紧了相关 API（见技术原理）。
- 目标场景：用 AirPods/Beats 的 Mac 用户、双 Mac 工作流（笔记本 + 台式机）、外设较多需统一管理的重度 Apple 生态用户。

## 怎么做的（技术原理/机制，事实层面）

- **运行方式**：原生 Mac app，菜单栏驻留 + 弹窗 + widget + Shortcuts 动作。要求 macOS 12 或更高（官网标注）。
- **设计语言**：第 3 代用 macOS Tahoe 的 Liquid Glass 风格重写 UI，菜单栏项、popover、widget 全部刷新。
- **Magic Handoff 机制**：评论中 Guilherme Rambo 确认底层仍是蓝牙解绑/重配对（unpair/repair），AirBuddy 做自动化包装；多数用户每日切换 1-2 次，< 3 秒可接受。
- **now-playing 集成的硬骨头**：maker 主帖与评论回复提到，Apple 在 AirBuddy 3 beta 周期中途收紧了 macOS 的 now-playing API，团队被迫重写为"通过代理后台进程路由 now playing 数据"的方案绕过限制。Rambo 称这是开发中遇到的最大 macOS 限制。
- **检测/技术栈**：CoreBluetooth + Swift/AppKit 原生开发；具体检测模型未公开。
