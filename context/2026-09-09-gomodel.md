## 是做什么的（如实复述，不评价）

GoModel 是一个用 Go 语言写的开源 AI 网关（AI gateway / AI control plane / AI proxy），把多家 LLM 厂商（OpenAI、Anthropic、Gemini、Groq、xAI、Bedrock、Ollama、vLLM 等共 31 家）封装成统一的 OpenAI 兼容 + Anthropic 兼容 API。开发者只需把客户端的 `base_url` 指向 GoModel，就能在不改业务代码的前提下切换模型、做路由、缓存、配额、审计和成本统计。

README 上的官方一句口号是 "The last AI gateway you will ever need"。产品形态是"单二进制 + 内嵌管理后台"，MIT 协议，可自托管，也可购买商业版 GoModel Pro 加 SSO、智能路由、Prompt 压缩等扩展。

## 解决什么问题（事实层面，不判断值不值得解）

- 想用多模型 fallback / 负载均衡，但不想每家厂商各写一套客户端：在客户端和上游 LLM 之间放一层网关统一收口
- 想跑内部统一的 LLM API（多团队共用），同时统计成本、限流、配 API key：GoModel 内置 budget、rate limit、虚拟 key、audit log
- 想保留 OpenAI/Anthropic 客户端 SDK 形态但不被任何一家网关锁定数据/费用：MIT + 自托管是它的卖点
- 想避免 LiteLLM 这类 Python 网关的"资源占用大、冷启动慢、线上莫名 500"问题（创始人 Jakub 在 PH 评论区亲述当初就是被 LiteLLM 500+ 问题逼出来自写）

## 跟 OpenRouter 比：少了什么、多了什么（事实层面）

| 维度 | OpenRouter | GoModel |
|---|---|---|
| 形态 | 托管服务（SaaS） | 开源自托管（核心），Pro 版为可选商业附加 |
| API 兼容 | OpenAI 兼容为主 | OpenAI + Anthropic 双兼容（`/v1` + `/v1/messages`） |
| 厂商数 | 100+（事实：单一受集成的上游池） | 31（OpenRouter 自身就是其中一家上游） |
| 数据出境 | 请求必须经过 OpenRouter 服务 | 自托管，请求不出本机/自家基础设施 |
| 路由策略 | 客户端可选模型 + 服务端自动 fallback | 显式权重轮询、成本路由、`cheapest_healthy`、sticky session、按模型配置 fallback 顺序 |
| 计费 | 按 token 经过 OpenRouter 抽成 | 自己持 key，无中间商抽成；Pro 版按公司年/月订阅，不按 token |
| 可观测 | OpenRouter 自己的 dashboard | Prometheus + OpenTelemetry OTLP + audit log + 内嵌 admin dashboard |
| SSO | 不适用 | Pro 版支持 OIDC（Okta、Entra ID、Google、Auth0、Cognito） |
| 智能路由 | 模型自动选 | Pro 版 Intelligent Routing（按请求分类挑便宜/健康档） |
| Prompt 压缩 | 无 | Pro 版（声称减少 2–20% 输入 token） |
| MCP gateway | 无 | 有（聚合 MCP 服务器到统一鉴权端点） |

简单说：**OpenRouter 是"我有上百家模型让你直接用、顺便抽成"，GoModel 是"MIT 单二进制让你自己跑、所有 key 自己拿"**。两者目标场景重叠，但商业模式和数据流向完全相反。

## 怎么做的（技术原理/机制，事实层面）

- **单 Go 二进制**：约 14.4 MB Docker 镜像（distroless、非 root、amd64/arm64/armv7 多架构）
- **统一 API**：`/v1/chat/completions`、`/v1/responses`、`/v1/embeddings`、`/v1/files`、`/v1/batches`、Realtime、WebSocket、WebRTC、TTS/转录；Anthropic `/v1/messages` + token counting
- **Provider passthrough**：`/p/:provider/*` 把原始请求直接转给上游厂商，零改动
- **存储**：默认 SQLite 零配置；可切 PostgreSQL、MongoDB
- **缓存**：两层——L1 精确匹配（请求体 hash，亚毫秒级）；L2 语义缓存（Qdrant / pgvector / Pinecone / Weaviate）。官方称"高重复场景 L2 命中率 ~60-70%，单 L1 仅 ~18%"
- **路由策略**：加权轮询、成本路由、`cheapest_healthy`（按错误率和中位延迟剔除 >20% 错误的候选）、sticky session（让同一会话固定打到同一家厂商，保留厂商原生 prompt cache 热状态）
- **重试 + failover**：transport 错误与 429/502/503/504 自动重试（默认 3 次 + 退避；流式响应不重试）；重试耗尽或遇到"重试也救不了"的错误码时切到 fallback；5 次连续失败触发熔断器，30s 内跳过该厂商/模型
- **Guardrails**：可插入 system prompt 注入、消息改写
- **可观测**：Prometheus `/metrics`、OpenTelemetry OTLP（GenAI 语义约定，兼容 Jaeger/Tempo/Honeycomb/Datadog）、audit log、admin dashboard 实时请求流、可选 pprof
- **MCP gateway**：聚合多个 MCP 服务器到统一鉴权端点，命名空间化工具
- **Plugin 系统**：支持 guardrails/filter/header edit/routing 策略，`.so` 插件启动加载
- **安全默认**（DEV.co 安全审阅指出）：`GOMODEL_MASTER_KEY` 默认未设 → 端点无鉴权；`LOGGING_LOG_BODIES` 与 `LOGGING_LOG_HEADERS` 默认开启 → 可能记录到敏感 token；未公开正式威胁模型/安全策略 → 生产部署需自行加固

## 定价 / 商业模式

- **开源核心（GoModel OSS）**：MIT，免费，自托管，二进制可商用
- **GoModel Pro**（商业分发，叠在 MIT 网关上）：
  - Prompt 压缩：声称减少 2–20% 输入 token，针对 agentic 流量
  - Intelligent Routing（beta）：按请求难度分类，挑"该档最便宜+最健康"的上游
  - OIDC SSO：Okta、Entra ID、Google、Auth0、Cognito
  - Per-Child Quota Templates：按子组织/团队配额
  - **价格**：$4,999/年 或 $499/月，按公司，不按席位
  - 离线签名 token 授权（无 phone-home）
  - 30 天退款保证；key 24h 内邮件送达
- **计费口径**：Pro 卖"License key"，不是 SaaS 订阅，无中间商按 token 抽成

## 评论区反馈（事实摘录，不评价）

> 来源：PH 产品页评论区，2026-09-09（仅摘录有实质内容的提问与官方回复）

- **Harini Mukesh**：自托管看起来不错，GoModel 什么时候决定在模型之间 failover、什么时候对同一厂商重试？
  - **Jakub 回复**：先重试再 failover，两段都可按厂商配置。重试用在"同一厂商下一秒大概率能恢复"——transport error + 429/502/503/504 默认重试，最多 3 次 + 退避；流式响应绝不重试。重试耗尽或遇到重试救不了的错时进 failover。
- **Tom Veber（Dial）**：我们目前 OpenRouter + 直连厂商 key 混跑，OpenRouter 是单点故障。自托管能不能让我按模型配置 fallback 顺序？
  - **Jakub 回复**：可以，GoModel 支持按模型配置顺序，既能写 config 文件，也能在 dashboard 上设（附 demo 链接）。
- **Gal Dayan（Dial）**：~20MB 单二进制 + MIT + 自托管比走第三方网关好推。问题是当某家厂商"还没全挂、只是延迟飘高"时 GoModel 怎么判？
  - **Jakub 回复**：目前只看错误不看延迟；延迟要等到 HTTP 超时（默认 10 分钟，prod 通常调到 ~30s）。叠加熔断器：5 次连续失败 → 跳过该厂商/模型 30s。`cheapest_healthy` 策略会跟踪错误率 + 中位延迟，自动剔掉 >20% 错误的候选。补一句：~20MB 是压缩后的 Docker 镜像大小。
- **Jakub 论坛置顶**："Open-source, self-hosted OpenRouter. What would make you try it in prod?"（顺便点名 LiteLLM PyPI 泄露、Portkey 迁 Palo Alto、TensorZero 停运）
