## 是做什么的（如实复述，不评价）

Eclatira 是一个面向开发者的实时多模态对话 AI 平台，把语音、视频、行动三件事放进同一个引擎：agent 能直接和用户语音对话，能"看见"摄像头或屏幕共享的画面，能通过 API/MCP/Zapier 真正动手执行操作。产品形态是 API + SDK 化的 runtime，外加一个 embeddable web widget 和电话渠道，开发者把它接进自己的应用即可获得"能看、能听、能说、能动手"的会话 agent。

创始人 Moad 在 PH 帖子里把定位表述为："Building live conversational video is a plumbing nightmare… Connect Eclatira to your application and your AI agent can: Speak naturally… See in real time… Take actions… Interact continuously."

## 解决什么问题（事实层面，不判断值不值得解）

- 自己拼装实时多模态管线很复杂：把流式语音、视频帧、工具调用同步到一个低延迟闭环里，要解决音视频对齐、缓冲、断流重连、模型推理延迟等多层问题。Eclatira 把这件事做成了一个统一的 runtime。
- 现有方案多是"几个模型拼起来"：语音用一个 stack（TTS/STT 或 voice-to-voice），视觉单独跑一个 CV 模型，工具调用再串一个 agent 框架，端到端延迟和体验割裂。Eclatira 强调三者在同一引擎里。
- 开发者做"能看到屏幕"的客服、销售、远程核验类场景时，传统做法是把"语音 agent + 视觉问答"分开集成。Eclatira 提供单次会话里 voice + vision + action 同时跑的方案。
- PH 评论里 Jack Hayes 直接点名："dealing with separate vision and voice models was such a pain" —— 创始人回应"And that's why we built this product"。

## 怎么做的（技术原理/机制，事实层面）

- 原生语音到语音（native voice-to-voice）引擎，全双工音频流，官方宣称 sub-800ms 响应延迟。
- 实时视觉管线：摄像头/屏幕共享流以最高 30 FPS 处理，包含 OCR、对象识别、画面变化检测。
- 多模态会话统一：音频与视频汇聚到同一个双向数据会话，不是分别处理后拼接。
- 行动层：支持 REST API、MCP 服务器、Zapier（号称覆盖 3000+ 应用）、Webhooks；agent 可以调用这些接口真正执行动作。
- 部署形态：embeddable web widget、电话渠道（呼入呼出）、版本化 REST API。
- 多语言：覆盖 100+ 种语言、387 种口音（官方卖点）。
- 数据处理：视频流不持久化存储；按区域的数据驻留（data residency by region）功能"即将推出"，目前不支持自托管。
- 内置动作护栏：可以通过 MCP/API 连接上设置 guardrails，限制 agent 能执行的动作范围（创始人 PH 回复）。
