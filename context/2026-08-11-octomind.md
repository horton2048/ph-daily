## 是做什么的（如实复述，不评价）

Octomind 是一个**CLI-first 的 AI agent 运行时**（用 Rust 写的单二进制，无运行时依赖，Apache-2.0 开源），由香港团队 **Muvon** 开发。本次上榜的 **Cloud + Hub** 是它的两个互补产品：

- **Octomind Cloud**：把 Octomind runtime 放到云端容器里跑。用户挑一台机器（可选 CPU/RAM、基础/Node/Python/Rust/自定义 Docker 镜像），给它一个任务，关掉笔记本后 agent 在云端继续跑；会话持久化，可从任意设备恢复并完整回放。计费按秒：只在 agent 实际工作时计全价，"思考"期间只计 RAM 费用（~$0.01/hr on Small），挂起后只收存储费。提供三档消费上限（4 小时 / 每周 / 每月）实时可见。
- **Octomind Hub（octohub）**：一个模型网关。一个 hub key（`om_…` 前缀的开发者 key）通过 OpenAI 兼容的 HTTP 端点（`https://hub.octomind.run/v1`）访问所有模型，无需自带 API key。它本身是开源的 Rust 项目，可自托管。底层用到 OpenRouter Model Fusion 做 model fusion。

runtime 本身还暴露五种入口：交互式 CLI、stdin 管道（给 CI/脚本用）、后台 daemon、WebSocket server、ACP 协议 sub-agent。还提供 "specialists & taps"（打包的领域 agent，单个 TOML 文件）、把 guardrails 写进脚本而非 prompt 的机制、按角色选模型 + 硬性消费上限、缓存感知的上下文压缩、按语义匹配激活的 skills。

注：tagline 里的 "27 models" 与 Hub 页实际列出的 32 个 chat/completion 模型（15 含 + 17 premium）不一致——可能是早期快照或营销取整，详见"未查到/待补"。

## 解决什么问题（事实层面，不判断值不值得解）

- **痛点 1：agent 是长时任务，笔记本不是长时机器**。创始人 Don Karter 在 PH 评论里说："Agents are long-running processes. Laptops are not long-running machines."——关上盖子 agent 就死了。
- **痛点 2：API key 管理分散**。评论里提到把五个 dashboard 的 API key 合并到一个 hub 登录。
- **痛点 3：单 agent 做 big task 会漂移/幻觉**。Vision 页明确提出应走多 agent 专业化、小而定义清晰的上下文路线，把 specialist agent 做成可像软件包一样安装的社区基础设施。
- **目标场景**：在云端跑长时间 agent 任务（编码、研究、多步 workflow），会话跨设备续接，单点统一计费与模型路由。

## 怎么做的（技术原理/机制，事实层面）

- **会话持久化 / relay 记录**：关 tab、断网后 "the turn keeps going and the relay records every step"。团队自述测试方式是 "killing browsers mid-turn until we couldn't lose a byte"。
- **按秒计费**：active 按秒计；思考/思考间隔只计 RAM；idle 5 分钟（免费）/ 15 分钟（Pro，可配）后挂起；挂起后只收存储费（10 GB 含，超出 $0.10/GB-月）。典型 5 分钟 agent 会话约 $0.0025。
- **模型路由**：默认配置把请求路由过 octohub 网关（`model = "octohub:auto"`）；BYOK（自带 key）始终是一等路径。
- **Specialists & Taps**：打包的领域 agent（如 `developer:general`、`doctor:blood`、`lawyer:sg`）从 tap 注册表取，每个是单个 TOML 文件；社区 tap 注册表在 `octomind-tap` 仓库。
- **Guardrails**："Policy lives in scripts, not prompts"——deterministic pre-call guards、post-result hooks、post-turn validators。
- **Benchmark 声明**：用 **GLM-5.2** 在 "real-PR benchmark" 上解了 24/25 题，号称 ahead of Claude Code（配 Opus）和 Codex。benchmark 博文在站内 blog。
- **技术栈**：Rust 单二进制；MCP 工具调用；OpenAI 兼容 HTTP；Docker 镜像；WebSocket；ACP 协议；TOML 配置。

## 定价 / 商业模式

模式 = **Freemium 订阅 + 按秒主机费 + 按 token 模型费混合**。"Cloud 不是第二个产品——一个订阅覆盖托管模型和机器"。

### Cloud 主机档

| 档位 | 价格 | 内容 |
|---|---|---|
| Free | $0 | 1 台 Small 机器、3 个模型、10 GB 存储、5 分钟空闲后睡眠 |
| Pro | $10 首月，之后 $20/月 | 解锁更多开源编码模型（有上限）；自定义 Docker 镜像；15 分钟空闲超时（可配） |
| Premium 模型 | 预付 credit 按 token 计 | Claude、GPT 等单独计费 |

Pro 的使用上限：$20/4 小时窗口 · $60/周 · $120/月；超出自动转预付 credit，会话不中断。并发：Free 1 路、Pro 2 路并行、Max 5 路、Team 15 路池化。

### Hub 模型定价（Hub 页实际列出 42 个模型）

- **Tier 1：含在所有付费档（15 个 chat 模型）**——超 cap 后 $0 边际成本。含 DeepSeek V4 Flash/Pro、Qwen3.7 Plus/Max/Flash、Qwen3.5 397B、Gemma 4 31B、GPT-OSS 20B/120B、MiniMax M3、Kimi 2.6/2.7 Code、GLM-5.2、Inkling/Inkling Small。其中 DeepSeek V4 Flash、Gemma 4 31B、GPT-OSS 20B 三款在免费层也有每日额度。
- **Tier 2：Premium（17 个 chat 模型）**——预付 credit 按 token 付。含 Claude Sonnet 5 / Opus 4.8 / Opus 5 / Fable 5、GPT 5.6 Luna/Terra/Sol、GPT 5.5 / 5.4 Mini/Nano / 5.5 Pro、Gemini 3.6 Flash / 3.5 Flash / 3.5 Flash Lite / 3.1 Pro、Kimi K3、Qwen3.8 Max。
- **Tier 3：Embeddings（10 个）**——任何档位从 credit 计。Voyage 4 系列、Jina v5 系列、OpenAI Embedding 3 Small/Large。本地 CPU embedding 各档免费。

Hub 页实际列出 **32 个 chat/completion + 10 个 embedding = 42 个模型**，与 tagline 的 "27 models" 数字不一致（详见未查到/待补）。

## 关联信息 / 生态

- **自定位**："specialist AI agents as community infrastructure"——agent 可像软件包一样安装，而非每次从零搭。roadmap：CLI/hosted specialist agents → premium tap marketplace（领域专家发布、其他人安装）→ 垂直行业 bundle → agent 作为社区共享资源。
