## 是做什么的（如实复述，不评价）

TrackMCP 是给 MCP（Model Context Protocol）服务器做的使用分析工具。接入方式是把现有 MCP server 包一层（`withTrackMCP(server)`，`npm i @trackmcp/sdk`），此后在仪表盘上回答四类问题（官网原话）：

1. **谁在用（Understand）**：哪些 AI 客户端连上来（Claude、Cursor、ChatGPT、自定义 agent），多少新客户端、多少回访
2. **在干嘛（Workflows）**：从第一个请求到出有用结果的完整路径，工具按什么顺序被调用，会话在哪一步停住
3. **成没成（Outcomes）**：哪些工作流真正到达结果、哪些需要再看一眼；客户端 7 天内是否回访（"returning clients come back within 7 days" 的口径）
4. **哪里坏（Reliability）**：请求在哪一步卡住、被重试、或结束却没有结果；错误摘要卡片示例——`send_email` 错误率 94%、平均重试 3.0 次、主因 schema 不匹配（agent 传字符串、schema 要数组），附建议修复

另外提供**每周英文洞察**（plain-English digest，附预计挽回调用量，如 "about 2,100 calls per week"）和**死工具检测**（官网示例："3 tools are dead: list_repos, get_customer, deploy_service received zero calls this week"）。

## 解决什么问题（事实层面，不判断值不值得解）

- **用了没人知道**：MCP server 作者只看到请求进来，不知道是哪个客户端、新用户还是回访用户
- **"成功"不等于"完成任务"**：评论区用户 Asad M. 举的场景——"工具返回 200 加一个空数组，agent 照样往下答，成功率看着健康但答案是错的"
- **错误藏在重试里**：工具描述写得差会让 agent 反复重试（Asad M.："一条写得差的工具描述导致了大部分重问"）；200 OK 状态码掩盖业务级失败
- **死工具**：server 里维护的工具可能根本没人调
- **传统栈只记录不解释**：官网的三层定位——"Logs recorded it. APM watched it. TrackMCP explains it"（Layer 01 服务器日志 / Layer 02 APM & tracing / Layer 03 TrackMCP 分析解释层）

## 怎么做的（技术原理/机制，事实层面）

- **接入**：`npm i @trackmcp/sdk`，包装官方 TypeScript / Python MCP SDK，无需手动打点（"no manual event tagging"），数据实时进仪表盘；集成片段即 `withTrackMCP(server)`
- **采集边界**：maker 在评论区明确——**不是代理，也不读 Claude Desktop**；而是包装现有 MCP server，从**服务端边界**发送"最小化遥测"（minimized telemetry）：客户端连接、工具调用、错误、延迟、重试、工作流结果；能采集哪些数据由 server 所有者控制
- **工作流/结果关联**：maker 称从 SDK 出发 100% 自动，无需显式插桩；机制是把"工具返回了什么 → agent 如何理解 → 下一步发生了什么"连起来，能识别 agent 是重试了、换了工具要更多信息、还是默默继续
- **数据管道示例**（官网图）：agents call tools → 流经 MCP server（+1 行代码）→ TrackMCP 捕获并合成 → 输出：谁在用（4 个 clients）、12 个活跃工具、3,120 个 sessions、发现 1 个静默失败
- **分析能力清单**（定价页矩阵）：工具调用数/排序/趋势、p50/p95 延迟与错误率、"藏在 200 OK 里的错误"、按客户端细分、调用检查器（参数/结果/耗时）、会话与漏斗、保存视图与自定义仪表盘、每周英文摘要、根因诊断+建议修复、影响预估（预计挽回调用数）、死工具检测、邮件/Slack/webhook/异常尖峰告警、REST API、CSV/数仓导出、自定义安全/SIEM 集成
- **存储**：托管 Postgres 基础设施（定价页 FAQ 自述）
- **能力边界**（maker 评论区答复）：自控 server 或可加 SDK 的可直接包；完全由第三方托管的 MCP server（如 Salesforce 托管）暂无法直接插桩，可行路径是把 TrackMCP 放在前面做轻量 proxy/gateway，保留鉴权/会话行为并观察 MCP 请求、参数、结果与后续调用
- **隐私路线**（maker 评论区答复）：工具名不够、参数才有上下文，但不盲记敏感文本；目标是让参数可查看，配脱敏/过滤/可配置保留期，再关联工具结果与 agent 下一动作；客户端侧（Claude/Cursor 等）采集要碰各家隐私与许可模式，maker 称这是 "hard part"，当前聚焦服务端
