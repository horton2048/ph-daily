## 是做什么的（如实复述，不评价）

Octri 宣称把一份 OpenAPI（亦接受 Swagger/Postman/AsyncAPI，归一到 OpenAPI 3.1）变成四件同步产物：可托管文档站（API Studio）、十种语言客户端 SDK（SDK Studio）、供 Agent 调用的 MCP 服务器、以及生产可观测（Monitoring）。规格变更会重建草稿与 diff，**批准后**才发版到注册表与文档。监控默认可关；既可编进生成 SDK，也可单独装后端包（Python/Node/Go 等）。

## 解决什么问题（事实层面，不判断值不值得解）

- 文档、SDK、Agent 工具与监控分属多套工具，易漂移
- 客户端报错往往事后才从工单得知
- Agent 靠记忆调 API 易幻觉，需要可调用的真实端点工具

## 怎么做的（技术原理/机制，事实层面）

- API Studio：三栏端点页、Try it、MDX 指南、自定义域名（Free 含）
- SDK：TS/Python/Go/Java/Dart/Ruby/PHP/Rust/Swift/Kotlin；可改名/排除端点/选 HTTP 引擎；自动发 npm/PyPI/Maven 等
- MCP：`npx @octri/mcp`；文档工具 + 每端点可调用工具；沿用 SDK 排除列表当权限
- Monitoring：日志、Issue 指纹、跨端瀑布、服务图、N+1、合成可用性、告警；客户端侧脱敏后再 ingest
- Spec audit：粘贴 OpenAPI URL 打分（官网演示）
