## 是做什么的（如实复述，不评价）

OmniVibe 是一个 AI agent 市场，把"agent 创作者"和"agent 使用者"聚到同一个平台。官方描述原话：

> OmniVibe brings specialized AI agents and the people who create them into one place. … a home for the agent creator economy.

产品分两端：

- **用户端**：告诉 OmniVibe 想完成什么，平台找到合适的 agent 并协调工作流；可以同时和多个 agent 协作，官方类比为"像在 Slack 上找你的同事发消息"。
- **创作者端**：内置 "Studio" 把一个想法变成可运行的 agent；可 refine、通过一条链接发布、分享给受众、追踪使用情况，并在他人使用时获得收益（earn when people use your creation）。

核心主张是"一个好 agent 不该只活在你的本地 harness、GitHub repo 或 SKILL.md 文件里"——它应该可被发现、可被使用、能为创作者创造价值。

## 解决什么问题（事实层面，不判断值不值得解）

- 创作者侧：很多 agent 被困在本地 harness / GitHub repo / SKILL.md 里，多数用户永远接触不到（评论区多位用户印证此痛点："so many cool agents buried in GitHub repos that most people will never find"）。
- 用户侧：不知道有哪些 agent 可用、哪个安全可用，发现与信任是两大阻碍（评论："the biggest blocker for me is discoverability and trust"）。
- 目标场景：把分散的 agent 变成可发现、可变现的 creator economy。

## 怎么做的（技术原理/机制，事实层面）

- **agent 发布机制**：创作者用 Studio 把已有的本地 agent（明确提到 SKILL.md 这类 Claude agent-skill 约定、GitHub repo、本地 harness）导入并发布，通过一条链接分发。
- **多 agent 协作**：用户端像 Slack 群聊一样同时与多个 agent 对话，平台负责协调工作流（"finds the right agents and coordinates the workflow"）。
- **变现机制**：创作者按 "qualified usage"（合格使用量）获得收益，官方未披露具体分成比例、计费口径或结算周期。
- **技术栈 / 运行方式**：未披露。未见开源信号（SKILL.md 是指被导入的 agent 约定，非 OmniVibe 自身开源）。
