## 是做什么的（如实复述，不评价）

Prized 是一个让**运营、支持、财务、RevOps 等非工程岗位**用 AI 自己构建内部工具的平台。数据源（Salesforce、Postgres、Zendesk 等）由管理员预先配置并批准，AI 建出来的工具**默认带企业级安全审计**，不需要工程师事后补安全。

定位是 **"Lovable for internal tools"**——Lovable 面向个人/外部应用，Prized 面向企业内部工具。

## 解决什么问题（事实层面，不判断值不值得解）

- 非工程团队有大量内部工具需求（运营仪表盘、支持面板、财务报表），传统路径是排队等工程师
- Lovable/Bubble 这类 AI 应用生成器面向外部应用，**默认没有企业级安全**（直接拿数据库凭据、审计缺失）
- Retool 这类需要工程师自己写代码，门槛对非工程师太高

## 怎么做的（技术原理/机制，事实层面）

Prized 把"AI 生成内部工具"的安全做得**默认开启**，关键机制：

- **Admin-approved connectors**：数据源（Salesforce/Postgres/Zendesk 等）由管理员预配置并批准，定义每个连接器能访问什么
- **Per-tool least-privilege**：每个工具拿到自己的数据库角色和集成 scope，不给 blanket 数据库访问
- **Credentials broker**：凭据对工具代码和智能体上下文不可见——以不透明占位符存储，通过 egress proxy 替换
- **Sandbox network policy**：默认 deny，只允许通过受控 proxy 的 host
- **LLM judge**：审查外部 API 调用，阻止危险操作
- **破坏性变更**：必须显式人类审批才能落地
- **Cross-schema 查询阻断**：未授权的跨 schema 查询会被阻断并记录
- **完整审计日志**：记录时间戳、操作者、动作、目标
