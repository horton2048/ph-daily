## 是做什么的（如实复述，不评价）

Bolcho AI 是一个面向印度市场（"Bharat"）的语音 AI 平台，让企业构建、部署和扩展多语言 AI 电话代理和 Web 聊天代理。核心是三段式 pipeline：Listen (STT) → Think (LLM) → Speak (TTS)，每段都支持多供应商自动 failover。它把电话（Plivo 托管或自带 SIP trunk）、LiveKit 实时媒体、可嵌入聊天组件、内置 CRM 打包在一起，开发者可自带 LLM/STT/TTS。官网自我定位："Voice AI for Bharat · Made with care in India"。

## 解决什么问题（事实层面，不判断值不值得解）

- **西方语音 AI 在印度失灵**：现有平台英文优先，对印度语言、区域口音、印地英语码切换（Hinglish）处理差，电话号码/订单号等数字识别错误率高。
- **通话延迟不够低**：印度语种多样+口音复杂，自然对话需要超低延迟，现有平台难以兼顾。
- **供应商锁定**：主流语音 AI 平台绑定单一 LLM/telephony 栈，开发者想换底层组件困难。
- **分钟费率加价**：多数平台对分钟数加价，印度价格敏感市场难承受。
- **目标场景**：销售、客服、医疗、教育、政务、预约、外呼跟进、网站聊天获客。

## 怎么做的（技术原理/机制，事实层面）

来源：bolchoai.in 官网 + PH 创始人评论

- **三段式 pipeline**：Listen (STT) → Think (LLM) → Speak (TTS)，每段支持多供应商，任一供应商失败自动 failover 到下一个。
- **语言锁（language director）**：逐轮锁定正确语言，当通话者中途切换语言时，实时切换代理语言。官网称支持 11+ 印度语言（Hindi、Tamil、Telugu、Bengali 等）+ Hinglish。
- **本地 turn-detector + 流式合成 + 自适应 barge-in**：减少对话延迟和打断处理。
- **prompt caching + 每句音频缓存**：重复输入 token 按 10-50% 计费，重复语音 ₹0。
- **API-first**：REST API、签名 webhooks、scoped API keys、server-side tools、structured outputs、idempotency。
- **自带模型**：开发者可自带 LLM、STT、TTS 供应商。
- **CRM 内置**：两向同步 Salesforce/HubSpot/Zoho/Pipedrive 或自带 CRM，支持 API 接入。
- **技术栈**（官网列出）：
  - STT: Deepgram、Sarvam (Saarika)
  - LLM: xAI Grok、OpenAI GPT、Anthropic Claude、Google Gemini、Sarvam
  - TTS: Sarvam、Azure、xAI Grok、ElevenLabs、Cartesia、Smallest
  - Telephony: Plivo 托管 / 自带 SIP trunk
  - 实时媒体: LiveKit
- **未查到/未答**：code-switching 中途切语言的具体准确率、电话号码/订单号等数字识别的回查机制（评论者 Jernej Jan Kočica 提出需 mid-call 字段校验，未获正面回答）、方言支持范围（Meghna Bharadwaj 问 dialect，未正面回答）。

## 评论区反馈（事实摘录，不评价）

- **Artem Fedorovich**（质疑）：多数语音代理一遇到印地语-英语 mid-sentence 码切换就崩；转录常把支付数字听错。问如何处理。
- **Igor Gurovich**（elder care voice AI builder）：自带 STT/TTS/LLM 灵活性是亮点。问码切换和实时语言边界检测。
- **Jernej Jan Kočica**（深度质疑）：电话里的 order number、phone number、pincode、email 等识别符——LLM 修复语法但不能修复听错的数字。"seven 和 nine 都很自信"。问 Bolcho 是否支持 mid-call 对业务自有数据做字段校验。
- **Meghna Bharadwaj**：是否考虑方言（dialects），语音代理常误判语法/方言。
- **Himani Sah**：是否覆盖所有印度语言。Kumar Ajay 回答"Yes"。
- **Arash Rahimi**（肯定）：不锁单一 LLM/telephony 栈很聪明，开发者一遇真实用量就想换底层。Kumar Ajay 回：把工程层挖得越深越不可阻挡。
- **未正面回答的问题**：码切换具体处理机制、方言支持、mid-call 字段校验。
